\title{Progressive Retrieval Attention on NVIDIA TensorRT-LLM:\\

\begin{abstract}
TensorRT-LLM provides paged KV caching, prefix reuse, in-flight batching, prioritized eviction, external KV connectors, and disaggregated prefill/decode serving. Progressive Retrieval Attention (PRA) introduces a different abstraction: immutable semantic resources selected by the current query and attached to attention without becoming ordinary sequential prefix state. This paper integrates the shared PRA runtime with TensorRT-LLM, preserving PRA's logical record, policy, authorization, and HOT/WARM/COLD/SOURCE contracts while delegating physical KV management to TensorRT-LLM. We evaluate geometry-matched E0 selected-text and E2 native-memory semantics, connector-backed persistence, online serving tails, HBM and transfer economics, shared-resource concurrency, and disaggregated KV transfer.
\end{abstract}

\section{Introduction}
Prefix caching answers whether the same preceding tokens were seen before. PRA answers which independently retained resource is relevant now. TensorRT-LLM is therefore a strong test of whether semantic non-prefix identity can compose with an already sophisticated physical KV subsystem rather than replace it.

\paragraph{Contributions.}
We target: (1) a PRA mapping onto TensorRT-LLM's paged KV manager and cache groups; (2) integration with the official KV Cache Connector; (3) scheduler-safe native non-prefix attachment; (4) online in-flight-batching measurements; (5) HBM/transfer and shared-resource economics; and (6) disaggregated prefill/decode evaluation.

\section{Background}
\subsection{PRA}
The shared runtime owns typed resource identity, selection, authorization, task/session policy, storage lifecycle, and OpenAI-compatible logical transport. Native K/V is derived state.

\subsection{TensorRT-LLM}
TensorRT-LLM manages paged KV blocks, request scheduling, prefix reuse, priority eviction, cache groups, external KV connectors, and optional disaggregated serving. These are physical execution mechanisms.

\section{Design}
\subsection{Three identities}
We require
\[
I_{\rm prefix}\neq I_{\rm PRA}\neq I_{\rm block}.
\]
PRA blocks must not enter prefix reuse under an identity that ignores the selected semantic resource.

\subsection{Connector-backed lifecycle}
PRA WARM/COLD persistence is mapped to the TensorRT-LLM KV Cache Connector where appropriate. PRA remains responsible for retention and authorization; the connector performs physical movement.

\subsection{Native attachment}
Selected blocks are attached request-locally, pinned for generation, and released without polluting ordinary prefix state. Source K/V is generated by the same TensorRT-LLM model path used by the matched E0 reference.

\section{Experimental Method}
\subsection{Geometry-matched E0/E2}
Selection, source K/V generation, suffix-prefill shape, positions, model, and decoding are frozen. Only ownership/attachment differs between ordinary prefix reuse and PRA-native memory.

\subsection{Online serving}
We run sustained arrivals through \texttt{trtllm-serve}, reporting TTFT/TPOT/completion p50/p95/p99, requests/s, output tokens/s, queue time, batch occupancy, preemption, cancellation, block occupancy, hits, eviction, and reload.

\subsection{Memory and transfer}
We report HBM, host/WARM bytes, H2D/D2H, PCIe/NVLink traffic, promotion latency, overlap, shared bytes avoided, and reload amplification.

\subsection{Disaggregated serving}
Where hardware permits, context and decode workers exchange KV using the supported TensorRT-LLM transfer path. We compare SOURCE, WARM, and already-resident PRA resource conditions.

\section{Priority and Quantized KV}
TensorRT-LLM's physical priority hints can be informed by PRA semantic retention without moving semantic policy into the engine. Native INT8/FP8 KV modes are evaluated separately from persistent PRA quantization; support does not imply sequence parity.

\section{Related Work}
We compare with PagedAttention-style KV virtualization, TensorRT-LLM prefix reuse, LMCache/external KV systems, disaggregated serving, cache eviction/compression, and RAG/context compression.

\section{Limitations}
Hardware topology may bound TP/disaggregation experiments. Results are reported per TensorRT-LLM/CUDA/model version and are not extrapolated across GPUs without measurement.

\section{Conclusion}
The goal is not another cache manager. PRA contributes semantic resource identity and lifecycle while TensorRT-LLM supplies optimized physical paging, batching, connectors, eviction, and transfer. The decisive question is whether that composition improves serving economics at unchanged model semantics.
