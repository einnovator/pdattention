\title{Progressive Context Control over Typed PRA Records}
\author{Jorge Sim\~ao\\EInnovator R\&D -- Center for the Sciences of Computation, Cognition, and Complexity}
\date{August 2026}

\begin{document}
\maketitle

\begin{abstract}
Large tool, database, log, graph, retrieval, file, and terminal results should
not enter an agent as one permanently visible token stream. We introduce
progressive model-controlled context disclosure over typed Parallel Reference
Attention (PRA) records. Each result has an exact scoped backing identity and a
compact summary registered as an implicit PRA document. Normal PRA routing
operates first over summary chunks, gists, and address metadata. If current
context is insufficient, a bounded controller may continue, activate the
known full record, materialize selected detail, search within that record,
advance or query a cursor, or call a new external tool. Every returned detail
is another typed view of the same source and re-enters PRA. This separates
discovery selection---which record or chunk is relevant---from escalation
selection---whether the current materialization is sufficient.

We correct two confounds in an earlier checkpoint by replacing its lexical
mechanism control with production Qwen3-0.6B PRA registration, hidden-state
gist routing, original-span selection, and native-K/V materialization, and by
calibrating the context controller on a disjoint validation split. The study
contains 30 balanced typed-record cases: 12 validation cases select one of two
frozen models, three fixed description levels/protocols, and a native routing
policy; 18 held-out cases then compare nine policies over five controller
seeds. We report visible-summary compression, full-backing Recall@1/2/4/8,
controller insufficiency and operation accuracy, and ingestion and inference
cost separately. On held-out cases, compact-only PRA reaches
\PaperSevenCalCompactRFour{} Recall@4, whereas production full-backing PRA
reaches \PaperSevenCalNativeRFour{}. The frozen controller is
\PaperSevenCalController{}. Native PRA, calibrated adaptation, oracle
adaptation, CCR, and full exposure respectively achieve
\PaperSevenCalNativeSuccess{}, \PaperSevenCalAdaptiveSuccess{},
\PaperSevenCalOracleSuccess{}, \PaperSevenCalCCRSuccess{}, and
\PaperSevenCalFullSuccess{} task success. The result distinguishes what
compression removes, what PRA can still address, and what a controller can
recover without conflating those mechanisms. The earlier action-conditioned
latent-trigger probe remains a secondary diagnostic.
\end{abstract}

\section{Introduction}

Tool-capable language-model agents increasingly spend their context budget on
observations rather than instructions. A database query can return thousands
of rows; a build command can produce megabytes of mostly routine output; a
graph traversal can expose a neighborhood whose useful branch is not yet
known. The agent often needs only a small projection now, but it may need a
different projection after its next inference.

Two common responses are incomplete. Full serialization couples active
context to source size. One-shot summarization breaks that coupling, but the
summary becomes both the model's visible evidence and its only clue that more
evidence exists. An exact original can remain in a cache while being
functionally unreachable: the model cannot request a detail whose relevance
was itself omitted.

This paper treats context management as a recursive PRA control problem. A
result is a typed record, not an undifferentiated message. Its compact view is
model-visible evidence; its full bytes remain exact backing state; and a
separate production PRA index provides retrieval-only addresses over those
full bytes. PRA first selects useful original backing chunks. The model then decides
whether to continue or request a bounded escalation. The returned view is
typed, linked to the same source identity, and routed again. Large collections
may expose cursors instead of repeatedly returning complete snapshots.

The contributions are:
\begin{enumerate}[leftmargin=*]
  \item a provider-neutral record model for nine result families and a stable
  mapping from each record to summary, full, selected-detail, search, and
  cursor-page PRA documents;
  \item a scoped content-addressed backing store with exact recovery, hash
  verification, TTL, size bounds, persistence controls, and audit events;
  \item deterministic type-specific compactors and independent lexical,
  entity, rare-term, and schema address views;
  \item a bounded \texttt{ContextAction}/\texttt{ContextDecision} API for
  continue, full, more, search, cursor, and external-tool transitions;
  \item stateful cursors supporting pages, ranges, filters, ordering, search,
  aggregation, sampling, field projection, and closure;
  \item a balanced six-class benchmark comparing compact-only indexing,
  lexical fallback, production full-backing PRA, calibrated model control,
  oracle adaptation, generic CCR retrieval, and full exposure;
  \item disjoint validation of semantic and hybrid native routing plus two
  controller capacities and flat/hierarchical protocols, frozen before the
  held-out five-seed matrix;
  \item separate measures of insufficiency recognition, mechanism correctness,
  task success, evidence recall, context/KV economy, expansions, and transfer;
  \item a secondary paired latent-trigger diagnostic and payload-scale
  transport study, retained without allowing either to define the main system.
\end{enumerate}

The main result is a decomposition, not a blanket win. Paper 7 separately
measures \emph{compression}, \emph{addressability}, and \emph{adaptation}.
This prevents a readable compact summary from being mistaken for a PRA gist,
and prevents a lexical search control from being described as native PRA.

\section{Context Is a Typed State Space}

Let a result record be
\begin{equation}
R=(id,\tau,P,A,V,B),
\end{equation}
where $id$ is a stable scoped identity, $\tau$ is a record type, $P$ contains
provenance and policy, $A$ is a set of address views, $V$ is the current
prompt-visible projection, and $B$ is lossless backing state. The model need
not see $A$ or $B$ directly. They belong to the runtime's control plane.

This separation prevents three category errors.
First, a compact view is not a retrieval index: prose that reads well may be a
poor rare-key index. Second, a cache handle is not authorization: identity
resolution must still enforce tenant and session scope. Third, storage is not
materialization: retaining bytes says nothing about when they enter the model's
active context.

Materialization follows a monotone visibility lattice:
\begin{equation}
V_0=\text{metadata}
\rightarrow V_1=\text{compact}
\rightarrow V_2=\text{selected fields/range}
\rightarrow V_3=\text{full}.
\end{equation}
The backing record does not change as a view advances. A selected row range is
computed from the hash-verified original after authorization, so an earlier
summary cannot silently become the source of truth.

\subsection{Compact views}

The inception implementation uses deterministic compressors because their
failure modes are inspectable. Database results retain column names, row count,
uniformly spaced representative rows, and min/max/mean statistics for numeric
columns. Logs prioritize lines matching error, exception, failure, fatal,
panic, denial, and timeout patterns before filling the remaining budget with
deterministic samples. Terminal records preserve command, exit status, working
directory, stderr, and bounded stdout head/tail. Graph records retain counts
and representative nodes and edges. Text-like records sample lines at fixed
relative positions.

These policies are baselines, not universal definitions of importance. Error
preservation helps logs in the current benchmark, while uniform text sampling
sometimes lands on a planted RAG trigger and usually misses it. Optional
generated summaries can be registered, but no generated summary is used in the
reported study.

\subsection{Address views}

Address views are built from exact input at ingestion time and stay outside the
prompt-visible compact payload. The current implementation emits deterministic
lexical tokens, entity-like spans, within-record rare terms, and structural
keys. The API reserves dense and native-Q/K views without pretending they are
implemented in this checkpoint.

For query $q$ and address view $A_j$, discovery is
\begin{equation}
\operatorname{score}(q,R)=\sum_j w_j\,s_j(q,A_j(R)).
\end{equation}
The inception lexical resolver uses exact normalized token overlap. It is
deliberately simple: its role is to test whether omitted bytes remain
addressable, not to establish a production semantic retriever.

\section{Lossless Backing State}

The local store serializes JSON-compatible values canonically and preserves
text and byte payloads exactly. A SHA-256 content hash defines the backing
identity within a tenant/session scope. Payload and manifest files reside under
a hash of that scope. Every read checks the caller scope, TTL, file presence,
and content hash before decoding.

The distinction between identity and authorization is operational. Knowing an
opaque content-addressed record handle does not permit a different session to
read it. Cursor reads repeat the same check. Deletion revokes both payload and
manifest; expiration removes them lazily on access or during cleanup. A bounded
store evicts oldest entries before accepting further state, and rejects one
payload larger than its configured capacity.

The current backend is local filesystem storage. The interface and transport
accounting allow a remote or distributed backend later, but this paper does not
report a remote storage service, network fault injection, encryption at rest,
or multi-process concurrency.

\section{Materialization and Transport}

Four retrieval modes share one authorization path.

\paragraph{Native typed event.}
The runtime accepts
\begin{equation}
\texttt{MATERIALIZE}(id,\;level,\;selector,\;cursor).
\end{equation}
The identity is already known, so expansion does not rerun semantic search.

\paragraph{Tool retrieval.}
\texttt{retrieve\_record} wraps the same event API for providers that expose
ordinary function calling. Equal payload and authorization behavior makes the
native event an optimization/interface choice rather than a semantic
requirement.

\paragraph{Mixed response and cursor.}
The initial result supplies bounded data, schema, \texttt{cursor\_id},
\texttt{has\_more}, and provenance. Later requests fetch only pages, ranges,
fields, aggregates, or matching rows.

\paragraph{Proactive expansion.}
The runtime may materialize a selected projection before the model asks. This
can repair a known risk pattern, but it shifts the burden to a policy that must
control false positives and transfer cost.

The storage policy is independent of retrieval mode. \texttt{upfront} places
the original at the model/server side; \texttt{on\_demand} retains it agent
side until expansion; \texttt{adaptive} chooses using topology, byte size, and
expected reuse. The study evaluates 100,000-byte and 1,000,000-byte thresholds
as configuration values. They are not proposed constants.

\section{Stateful Cursors}

A cursor is a scoped capability over a collection, not a copy of that
collection. Its state includes record identity, source, query, schema,
collection name, position, page size, filters, ordering, total estimate,
creation and expiration times, provenance, authorization fingerprint, and a
continuation handle. Supported operations are next/previous page, bounded
range, search, filter, numeric aggregate, deterministic sample, selected-field
projection, and close.

Cursors matter when the next useful projection depends on the previous result.
An analytics agent can request an aggregate, notice an outlying subgroup, and
then inspect only rows in that subgroup. A graph agent can inspect one
neighborhood before continuing traversal. Repeating a full tool call would
discard position and may recompute or mutate source state.

The current cursor manager is in-process and read-only. It does not yet provide
transaction isolation, snapshot versioning, distributed leases, or recovery
after process loss. Those are serving requirements, not properties inferred
from the mechanism tests below.

\section{Progressive PRA Context Control}

\subsection{Implicit documents and source identity}

In Paper 7, a compact result is not merely appended as a flat message. For
record $R$, the runtime registers a stable document such as
\texttt{record://R/summary}. Its serialized typed view is split into bounded
chunks; each chunk receives a stable ID, routing gist, lexical/entity address
metadata, and the native source identity of $R$. When a PRA-aware Hugging Face
model is attached, registration calls the same \texttt{add\_reference} path as
an ordinary document. The production tokenizer, chunker, hidden-state encoder,
gist builder, and native-K/V cache are therefore reused rather than simulated
by a result-specific attention path.

Derived documents include \texttt{record://R/full}, selected detail, search
results, and cursor pages. They share record ID, authorization scope,
provenance, and backing fingerprint. Activating \texttt{FULL} for a known
record is exact identity resolution, not a second global semantic search.
This distinction matters operationally: discovery asks which source is
relevant; escalation asks how much of that already identified source is needed.

\subsection{Bounded decisions}

The controller emits a typed decision
\begin{equation}
D=(a,id,s,q,c,t),
\end{equation}
where $a$ is one action, $id$ a known record, $s$ a typed selector, $q$ an
in-record query, $c$ an authorized cursor, and $t$ an external tool. The action
space is:
\begin{center}
\small
\begin{tabularx}{.96\linewidth}{@{}lX@{}}
\toprule
Action & Runtime meaning \\
\midrule
\texttt{CONTINUE} & Current PRA-selected context is sufficient. \\
\texttt{MATERIALIZE\_FULL} & Activate the exact bounded backing record. \\
\texttt{MATERIALIZE\_MORE} & Expose declared fields, rows, lines, chunks, or a neighborhood. \\
\texttt{SEARCH\_RECORD} & Search inside one known large backing object. \\
\texttt{CURSOR\_NEXT/QUERY} & Continue or refine an authorized stateful cursor. \\
\texttt{CALL\_TOOL} & Acquire information absent from retained backing state. \\
\bottomrule
\end{tabularx}
\end{center}

The parser rejects unknown record IDs, cursor IDs, selectors, and tools before
execution. A local PRA-aware deployment can express $D$ as a native context
event. A remote opaque model can use special retrieval tools. Mixed deployment
uses native activation for co-located records and callbacks for remote state.
These transports implement the same logical transition.

\subsection{Recursive control loop}

For query $q_t$ and active typed documents $\mathcal{V}_t$, PRA first computes
\begin{equation}
S_t=\operatorname{PRASelect}(q_t,\mathcal{V}_t;K).
\end{equation}
The model then emits $D_t$. If $D_t$ expands state, the runtime authorizes and
executes it, produces typed view $V_{t+1}$, registers that view as an implicit
PRA document, and repeats:
\begin{equation}
\mathcal{V}_{t+1}=\mathcal{V}_t\cup\{V_{t+1}\}.
\end{equation}
The loop has a hard step bound. The model never returns the hidden payload
itself; it returns only a decision whose identifiers are resolved by the host.

\section{Calibrated Full-Backing PRA Study}
\label{sec:calibrated-full-pra}

\subsection{Three independently measured mechanisms}

For this study one typed record is represented as
\begin{equation}
R=\{V_{\mathrm{compact}},A(B_{\mathrm{full}}),B_{\mathrm{full}}\}.
\end{equation}
$V_{\mathrm{compact}}$ is an agent-side summary, schema, statistics block, or
sample and is visible to the controller. $A(B_{\mathrm{full}})$ contains PRA
routing addresses built from every original backing chunk and is never shown
as evidence. $B_{\mathrm{full}}$ is exact scoped state. A PRA gist is therefore
an address encoding, not a second name for the visible compact summary.

The production path calls \texttt{PRAForCausalLM.add\_reference} on the exact
backing serialization. Qwen3-0.6B tokenizes the source, forms 32-token chunks
with eight-token overlap, encodes 128-token model-safe blocks, constructs
hidden-state mean gists at layer 27, and retains native K/V for the selected
original spans. Routing is bounded to eight candidates; reported Recall@$K$
uses $K\in\{1,2,4,8\}$ and gives credit only when the union of selected spans
fully covers the evidence marker. One-token consumption checks verify native
K/V use; repeated controller seeds replay the immutable selections through the
same typed materialization API rather than rebuilding the index.

The benchmark keeps five instances of each of the six action classes defined
in the earlier checkpoint below. Billing and deployment form the 12-case
validation partition; inventory, identity, and support form the 18-case test
partition. Within each partition, cases distinguish compact-explicit evidence,
natural semantic omission (for example, ``payment authentication failures''
versus ``merchant token expired''), opaque identifiers, and evidence absent
from backing state. The answer marker is never silently inferred: we record
whether it is literal in the compact view, present in the full-backing index,
covered by the selected original spans, and visible after materialization.

\section{Earlier Progressive-Context Checkpoint}

\subsection{Questions and frozen protocol}

This earlier checkpoint asked: (RQ1) when is a compact typed view sufficient; (RQ2)
can the model recognize insufficiency; (RQ3) what does automatic PRA recover
before explicit escalation; (RQ4) does the controller choose full, partial,
search, cursor, or tool correctly; and (RQ5) how close does PRA plus model come
to FULL at lower exposure cost?

The benchmark contains 30 identities, five in each balanced class:

\section{Why Reversibility Is Not Enough}

Storage reversibility answers: ``Can the original be recovered if its identity
and relevance are known?'' Agent behavior asks a harder question: ``Will the
model realize that an omitted detail should change what happens next?'' We
separate three cases:
\begin{enumerate}[leftmargin=*]
  \item \textbf{explicit insufficiency}: the query names the hidden concept;
  \item \textbf{latent insufficiency}: the hidden concept is required but is
  absent from the query;
  \item \textbf{action-trigger omission}: the hidden detail would select a
  different downstream action or tool.
\end{enumerate}

For a compact view $V_c$, define
\begin{equation}
\mathrm{TriggerRecall}
=P(\text{required downstream action remains reachable}\mid V_c).
\end{equation}
The definition intentionally includes more than answer overlap. A benchmark
must observe whether evidence is visible, whether expansion occurs, whether the
correct next action remains selectable, and whether an index or proactive
policy repairs an omission.

\section{Secondary Substrate Mechanism Checks}

\subsection{Protocol}

The study uses seeds $\{11,23,37,53,71\}$ and nine result types per seed,
giving \PaperSevenTypedRecords{} records. Each payload contains one rare
identifier and one required-action token placed away from ordinary high-salience
content. Type policies receive a four-unit compact-view budget. No language
model, learned compressor, embedding model, or native-Q/K router participates.

We record serialized bytes before and after compression, exact backing
equality, trigger presence in the compact view, retrieval by an explicit rare
identifier, retrieval by the generic latent query ``continue safely,'' and
retrieval by a proactive probe that names the candidate action. The last
condition is an upper-bound mechanism check: it assumes a policy has already
generated the correct candidate action. It is not an autonomous latent
discovery result.

M4 compares four APIs on the same 100-row database shape. Native-event and tool
conditions request full state. Mixed mode opens a five-row cursor page.
Proactive mode selects rows 0--4. Reported timing is local Python wall time and
is not a model/server latency claim. M5 filters a subgroup, computes its mean,
and finds an anomaly through a cursor. M6 executes policy decisions for 10K,
100K, and 1M text payloads at low and high expected reuse across four declared
topologies. The topology sweep tests accounting logic; it does not instantiate
four physical deployments.

The adaptive policy keeps same-process state effectively upfront because no

\section{Secondary Action-Conditioned Recovery}

\subsection{Paired protocol}

The second study keeps the record substrate fixed and changes the recovery
policy. Thirteen deterministic cases cover entity, alias, number/date, rare
string, relation, action, state transition, permission, dependency, error
code, backend type, schema type, and threshold/anomaly clues. In every case,
one hidden field changes the required action. The explicit query names that
field; its paired latent query states only the operational goal. The compact
view is checked to omit the planted trigger. This is a controlled mechanism
benchmark, not a sample of production agent traffic.

We cross the 13 pairs with eight policies and seeds
$\{11,23,37,53,71\}$, yielding \PaperSevenNextRows{} rows. Candidate-action
palettes contain four IDs. The frozen controller is Qwen3-0.6B, Ollama blob
\texttt{sha256-7f4030...e1fa}, with temperature zero, JSON-constrained output,
thinking enabled, and at most four generated hypotheses. A malformed JSON
response counts as no decision; it is not repaired with the answer key. Full
context is included as a model-capability ceiling.

The policies are compact-only; model-emitted CCR retrieval (CCR-E); proactive
lexical CCR expansion (CCR-P); explicit retrieval followed by proactive
fallback (CCR-M); generic search over deterministic address views; one probe
per candidate action; up to four model-generated hypotheses; and full context.
The CCR variants reproduce public architectural behavior---a compact typed
view, exact local original, stable marker, retrieval tool, and optional
proactive expansion---without claiming implementation identity with any
specific system.

We preserve the causal chain
\begin{equation}
\text{goal}\rightarrow\text{hypothesis}\rightarrow\text{address}
\rightarrow\text{materialization}\rightarrow\text{action}.
\end{equation}
TR-address requires a useful hypothesis and target-record address hit;
TR-materialize requires exact evidence containing the planted trigger; and
TR-action requires the final candidate action. We additionally record false
expansions, expansion precision, bytes, estimated tokens, model/tool calls,
and local search time. Wilson intervals describe policy-cell proportions.
Paired differences use a 10,000-draw bootstrap over 13 trigger cases after
averaging the five seeds, so repeated decoding seeds are not treated as new
task identities.

\section{Security and Reliability Contract}

Typed adaptive context creates capabilities to reveal hidden state. Its
security boundary must therefore be explicit.

\begin{itemize}[leftmargin=*]
  \item Authorization precedes full reads, selected ranges, cursor opens, and
  every cursor page operation.
  \item Record IDs and cursor handles are opaque locators, never bearer
  authorization.
  \item Tenant and session scope are part of identity resolution; the test
  suite rejects cross-session reads.
  \item TTL and explicit deletion revoke state; content hashes detect local
  payload corruption before decode.
  \item Audit rows record ingestion, expansion, denial, cursor open, and cursor
  fetch events with scope and timestamp.
  \item Redaction is not yet implemented. A production policy must apply it to
  both compact and full views so expansion cannot bypass disclosure controls.
\end{itemize}

The store currently writes local plaintext. Encryption, key rotation,
distributed authorization, concurrent mutation, cursor revocation propagation,
and audit durability remain open production gates.

\section{Relationship to Prior Systems}

Prompt-compression methods such as LLMLingua and LongLLMLingua learn or compute
shorter prompt representations under token budgets
\cite{jiang2023llmlingua,jiang2023longllmlingua}. Paper 7 is orthogonal to the
choice of compressor: it specifies where an exact original lives and how
different views are addressed and materialized. A learned compressor can be
registered without becoming the backing state.

MemGPT frames long-context management as movement between memory tiers and
uses explicit control flow to manage what enters context \cite{packer2023memgpt}.
Paper 7 shares the tiered-state intuition but centers typed tool results,
selective fields/ranges, deployment transport, and cursor operations.
Retrieval-augmented generation supplies external evidence to a generator
\cite{lewis2020rag}; here, a RAG result is itself one typed record that may be
compacted, re-addressed, and progressively inspected.

Headroom's public Compress--Cache--Retrieve documentation describes
type-aware tool-output compression, local hash-indexed original caching, a
model retrieval tool, markers, and proactive expansion \cite{headroom2026ccr}.
That architecture is a strong reversible baseline. Paper 7 does not claim that
Headroom fails. The primary comparison instead asks whether a typed controller
can choose among bounded full, partial, search, cursor, and tool actions rather
than exposing only retrieve-or-continue. At nearly full materialization cost,
the generic CCR baseline is strong when retained backing state contains the
answer, but it cannot acquire absent C5 evidence and does not identify which
bounded mechanism was needed. The secondary paired study asks the narrower
reachability question: when a compact view omits the fact that would make
retrieval relevant, what address or policy keeps the downstream action
reachable? Explicit proactive recovery is reliable, generic latent recovery is
nearly unchanged from compact-only, and action-conditioned expansion improves
the downstream action at substantial exposure cost. These are policy results,
not claims about a particular commercial implementation.

Paper 6.5's typed capability work separates broad tool/skill discovery from
bounded selection and exact full-schema activation. Paper 7 preserves those
capability records and adds the result side of the interaction: what happens to
a typed observation after a tool executes. The companion Paper 3.1 motivates
multiple address views by showing that one generated summary can be a brittle
retrieval key. The present study tests that design principle with deterministic
records rather than repeating its summarization experiments.

\section{Limitations and Next Gates}

The primary benchmark is a controlled mechanism checkpoint, not a natural
agent workload. It has 30 identities and five decoding seeds; seeds measure
controller variability, not population diversity. ANSWER\_CODE is
machine-readable after exposure, which isolates context control but
understates interpretation difficulty. The balanced capability descriptors
also make the correct mechanism more explicit than many real tool results.
Consequently:

\begin{enumerate}[leftmargin=*]
  \item the new production path uses one Qwen3-0.6B routing backend, one routing
  layer, 32-token chunks, and semantic/hybrid mean gists; addressability may
  change with model family, layer, chunk geometry, or learned QK compression;
  \item controller calibration compares only Qwen3-0.6B and Llama-3.2-3B on 12
  validation cases, so the selected configuration is a bounded experimental
  default rather than a general model leaderboard;
  \item the exact answer-code read gate isolates context recovery and makes
  final use deterministic once evidence is visible; natural free-form answer
  generation remains a separate evaluation gate;
  \item CCR\_TOOL's binary mechanism score is not directly comparable to
  choosing among full, partial, search, cursor, and a new external tool;
  \item C3 validates cursor sufficiency decisions and bounded pages, not
  multi-step transactional analytics or mutable remote snapshots;
  \item C5 simulates the returned external tool record after a valid call; it
  does not evaluate broad tool discovery or side-effect safety;
  \item topology measurements are policy accounting, not physical network or
  distributed-store benchmarks;
  \item native-K/V consumption is verified by live generation checks and then
  inferred from the production requested-token count for repeated frozen
  selections; end-to-end accelerator memory and TTFT need larger workloads;
  \item redaction, remote-store fault tolerance, and distributed cursor leases
  remain absent.
\end{enumerate}

The next gate is external replication on fresh natural tool-result tasks, with
class-balanced abstention thresholds and no gold-derived features. It should
retain production PRA's low-cost backing recovery while adding bounded full,
cursor, and external-tool escalation without turning every compact-sufficient
case into retrieval.
Native PRA-aware events and remote function-call adapters should then be
compared at matched semantics while measuring TTFT, active K/V, transfer,
callback count, and store latency.

\section{Conclusion}

Agent context is structured state with a lifecycle, not merely text waiting to
be truncated. Paper 7 implements progressive context disclosure over typed PRA
records: compact results become routable implicit documents; full bytes retain
exact scoped identity; bounded decisions activate full, selected, searched,
cursor, or newly acquired state; and each returned view recursively re-enters
PRA.

The calibrated experiment separates what this architecture already solves
from what it does not. Compact-only PRA reaches
\PaperSevenCalCompactRFour{} held-out Recall@4 after visible compression,
whereas the validation-frozen full-backing native policy reaches
\PaperSevenCalNativeRFour{}. Native PRA achieves
\PaperSevenCalNativeSuccess{} task success at
\PaperSevenCalNativeTokens{} materialized tokens; calibrated and oracle
adaptation reach \PaperSevenCalAdaptiveSuccess{} and
\PaperSevenCalOracleSuccess{}. CCR and full exposure reach
\PaperSevenCalCCRSuccess{} and \PaperSevenCalFullSuccess{} while spending
\PaperSevenCalCCRTokens{} and \PaperSevenCalFullTokens{} tokens. These values
make controller-realized improvement and oracle mechanism headroom visible
instead of attributing both to ``PRA plus model.''

The scientific conclusion is therefore specific. Full-backing production PRA
can preserve addressability after a small visible summary omits decisive
evidence. Progressive typed operations provide a bounded route from that
selection to additional state, and validation-calibrated control reveals how
much of the oracle headroom the tested controller realizes. The earlier
lexical result remains useful as a mechanism control, not as evidence for
native PRA. Future gains must improve controller reliability and replicate the
routing result without erasing PRA's bounded-context advantage through
indiscriminate materialization.

\section{Public API Sketch}

The backing facade keeps deployment policy separate from records. The
progressive facade registers compact and derived views through PRA:

\begin{lstlisting}[language=Python,basicstyle=\ttfamily\scriptsize]
policy = ContextPolicy(
    storage="adaptive",
    local_store="./tmp/pra",
    retrieval_mode="mixed",
    topology="remote_model",
    record_policies={
        RecordType.DB_RESULT: TypeContextPolicy(unit_limit=8),
    },
    cursor_policy=CursorPolicy(page_size=20, max_page_size=200),
)
backing = AdaptiveContextRuntime(
    RecordScope(tenant_id="tenant-a", session_id="session-42"),
    policy,
)
context = ProgressiveContextRuntime(backing, pra_model=pra_model)
record = context.ingest(
    tool_result,
    record_type=RecordType.DB_RESULT,
    capabilities=RecordCapabilities(
        full_available=True,
        full_bounded=False,
        searchable=True,
        partial_selectors=("rows", "fields"),
    ),
    provenance={"tool": "query_orders", "call_id": "call-17"},
)
\end{lstlisting}

The model first receives the compact typed view. Independently, the host may
register exact backing state through production PRA and materialize only the
selected original spans:

\begin{lstlisting}[language=Python]
context.register_backing_record(record.record_id)
native = context.native_select("failed payments for ACME")
detail = context.materialize_native_selection(native, top_k=4)
# detail preserves record_id and contains decoded original spans.
\end{lstlisting}

The controller's JSON is parsed against active record/cursor/tool allowlists;
executing a valid transition registers the returned detail as another typed PRA
view:

\begin{lstlisting}[language=Python]
selection = context.automatic_select(
    "failed payments for ACME", top_k=4,
)
decision = parse_context_decision(
    model_json,
    allowed_record_ids=tuple(backing.records),
    allowed_cursor_ids=backing.cursors.cursor_ids,
    allowed_tools=("query_payment_provider",),
)
transition = context.execute(decision, transport="mixed")
# transition.produced_document is now active in the PRA registry.
\end{lstlisting}

The direct convenience operations share the same path:
\begin{lstlisting}[language=Python]
full = context.materialize_full(record.record_id)
detail = context.materialize_more(
    record.record_id, {"rows": [100, 120]},
)
matches = context.search_record(
    record.record_id, "failed payments for ACME",
)
page = context.cursor_next(cursor_id)
\end{lstlisting}
