# Paper 4: PRA-aware training

## Central question

Can transformer plasticity make sparse external native K/V useful as a learned
computational primitive, rather than only an inference-time retrofit?

## Claim boundary

Gate 0 fixes oracle memory identities and trains only memory production and
consumption. Do not describe it as learned routing. Do not escalate the paper's
claims beyond the completed tier recorded in `paper4_findings.json`.

The external-memory fixture validates read-side state transitions, cache
accounting, invalidation, and security isolation. Its `answer_proxy` is required
document availability, not LM answer quality. Keep cold external gists, warm
model-native encodings, and hot materialized K/V distinct.

Gemma G0--G6 status is recorded under `gemma_gate/gemma_findings.json`. Exact
native global-slot conversion and adaptation scopes are ready, but no Gemma
quality or training claim is allowed before measured runs replace the pending
artifact rows.

Paper 4 owns authenticated read-side admission and learned memory consumption.
Paper 4.5 owns writes, consolidation, merging, forgetting, and conflict handling.

## Reproducibility

Tier-0 values must be generated by `summarize_tier0.py`; lifecycle values by
`run_external_memory_lifecycle.py`; and the Gemma plan by
`prepare_gemma_gate.py`. Private checkpoints are not paper artifacts.
