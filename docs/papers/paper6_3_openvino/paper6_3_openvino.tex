\begin{abstract}
OpenVINO GenAI provides continuous batching, bounded K/V scheduling, prefix
caching, eviction controls, and execution across Intel CPU, GPU, and NPU
devices. Progressive Retrieval Attention (PRA) adds semantic, query-addressed
resources that must remain distinct from sequential prefixes. We implement an
OpenVINO provider, an E0 selected-text adapter, and tested contracts for
topology-bound native K/V handles, authorization, request pinning,
exactly-once attachment, cleanup, and prefix-pool exclusion. A live audit of
OpenVINO 2026.3.1 and OpenVINO GenAI 2026.3.1.0 confirms all required
continuous-batching controls, but finds no public operation for attaching
arbitrary selected non-prefix K/V. We therefore report native E2 as blocked,
not as an implicit consequence of prefix caching. On Qwen2-0.5B-Instruct INT4,
selected-text and full-context E0 recover the controlled answer in every
evidence-bearing request on an Intel i7-1355U CPU and Iris Xe GPU. Selected
text uses 63 input tokens instead of 1,573. On GPU it reduces cold TTFT from
1,129.6 to 102.9 ms. Under explicitly warmed continuous batching at eight
shared requests, it reaches 8.48 requests/s rather than 7.39 and reduces TTFT
p99 from 297.7 to 148.9 ms. The result establishes a reproducible transport
baseline and a precise extension boundary; it does not establish native
OpenVINO PRA parity or memory savings.
\end{abstract}

\section{Introduction}
An inference engine's prefix cache identifies previously computed sequential
token histories. PRA identifies immutable logical resources selected by a
query. These identities have different lifetimes and authorization rules:
\[
I_{\mathrm{prefix}} \ne I_{\mathrm{PRA}} \ne I_{\mathrm{physical}}.
\]
Identical visible prompts may select different protected resources, while the
same resource may be shared safely by many sessions. A correct OpenVINO
integration must preserve that distinction while allowing OpenVINO to keep
control of compiled execution, K/V blocks, eviction, and batching.

This study makes three contributions. It implements the PRA-side OpenVINO
contracts, audits the installed GenAI scheduler and pipeline interfaces, and
measures a common E0 workload across CPU, GPU, prefix reuse, and continuous
batching. The audit also identifies the smallest missing native mechanism:
request attention metadata cannot currently receive an arbitrary selected
non-prefix K/V set through the public Python API.

\section{Claim Boundary}
E0 renders selected source text into the visible prompt. E1 may retain derived
engine state without exposing arbitrary selected K/V to attention. E2 consumes
that K/V natively, preserving source geometry and combining local and memory
scores in one softmax. All model measurements in this paper are E0. The native
classes described below are executable lifecycle contracts, not evidence that
OpenVINO already performs E2.

\section{OpenVINO Mapping}
\subsection{Responsibility split}
PRA owns typed records, selection, authorization, task/session policy, semantic
retention, and a four-tier storage lifecycle. OpenVINO owns compilation,
device execution, sequential K/V blocks, prefix reuse, batching, and physical
eviction. Physical tensor handles are derived state bound to a specific model,
revision, device, precision, layer count, K/V-head count, and head dimension.

\subsection{Implemented code}
\texttt{src/pra\_openvino/adapter.py} provides
\texttt{OpenVINOEngineAdapter}. Its HTTP/OVMS form is explicitly E0. It reports
E2 only when an application supplies an \texttt{OpenVINONativeExecutor};
package installation or prefix-cache availability is never enough.

\texttt{src/pra\_openvino/native.py} provides a topology fingerprint,
immutable K/V handles, a physical-store protocol, an in-memory deterministic
store, and \texttt{OpenVINONativeAttachmentManager}. The manager validates
topology before registration, authorizes a complete routed set before
scheduler admission, pins it for the request lifetime, returns it exactly
once, and unpins it during cleanup. A shared isolation guard rejects any PRA
logical key offered to the ordinary sequential/prefix pool. Focused tests cover
topology mismatch, cross-tenant access, duplicate attachment, cleanup, and
capability honesty.

\subsection{Live API boundary}
\texttt{SchedulerConfig} exposes cache size or K/V-block count, sequence and
batched-token limits, prefix caching, dynamic split/fuse, and cache eviction.
Supplying this configuration activates continuous batching. The public
\texttt{LLMPipeline} surface exposes generation, tokenizer/config access, and
chat state. It does not expose selected external K/V, non-prefix tensor
attachment, or an attention-metadata callback. Prefix caching therefore
accelerates repeated visible histories but does not implement PRA E2.

\section{Experimental Method}
\subsection{Environment}
The remote Windows host runs Python 3.10.0, OpenVINO 2026.3.1, OpenVINO GenAI
2026.3.1.0, and OpenVINO Tokenizers 2026.3.1.0. Available devices are a 13th
Gen Intel Core i7-1355U CPU and Intel Iris Xe integrated GPU; no NPU is
available. The model is OpenVINO Qwen2-0.5B-Instruct INT4. Scheduler settings
use a 1 GiB cache, eight sequences, 2,048 batched tokens, prefix caching, and
dynamic split/fuse. Greedy decoding is capped at 24 new tokens.

\subsection{Conditions}
The target resource contains \texttt{PRA\_EVIDENCE\_4821}; distractors contain
different codes. The five one-shot conditions are no evidence, stable prefix
only, selected text, prefix plus selected text, and full retained context. The
same evidence is used in selected and full conditions. Each condition is run
five times independently on CPU and GPU.

The direct \texttt{ContinuousBatchingPipeline} experiment uses selected text
and full context under shared-resource and independent-resource workloads.
Concurrency is 1, 2, 4, and 8 with five measured waves. Every distinct resource
is primed outside the timed interval. Reported p95/p99 values are smoke
descriptors over small cohorts, not production service-level estimates.

one-resource smoke.

process and 39.40 s for the first GPU one-shot process. The later direct
continuous-batching GPU process constructs in 5.05 s after system/model caches
have been populated; these are cold-process observations, not comparable
steady-state request latencies.

With one shared resource and concurrency eight, selected text reaches 8.48

transport or concurrency. The current experiment therefore supports a token
and latency claim, not an engine-memory saving claim.

\section{Interpretation}
OpenVINO prefix caching and PRA selection address different reuse axes. When
the same full context is repeatedly visible, prefix caching can make its warm
TTFT competitive with selected text. When requests arrive concurrently,
shorter selected inputs reduce scheduler work and improve the shared-resource
frontier in this smoke. Native PRA would target a harder regime: encode a
resource once, select different non-prefix intervals for many queries, and
avoid making those source tokens visible. That regime cannot be measured until
the attention attachment seam exists.

\section{Required Native Extension}
A minimal extension should accept an authorized set of topology-matched K/V
handles plus source positions at request admission. The scheduler must pin the
set, keep it outside ordinary prefix identity, expose it once to attention, and
release it on completion or cancellation. Attention must normalize local and
memory scores jointly. A geometry ladder should then compare ordinary prefix,
geometry-matched cached source, full native source, sparse multi-record source,
and cached decode before any economics claim.

\section{Limitations}
The controlled task verifies evidence transport, not natural QA. Only one
small INT4 model, one CPU, one integrated GPU, and five waves are measured.
There is no OVMS process, NPU, native K/V parity, device-memory telemetry,
long-session pressure, eviction sweep, or natural QASPER/Hotpot/2Wiki cohort.
All serving results are E0.

\section{Conclusion}
PRA can coexist with OpenVINO's public serving abstractions at E0 while
preserving semantic identity and explicit capability reporting. Selected text
substantially reduces cold ingestion and improves the shared-resource
continuous-batching frontier on the tested GPU. OpenVINO GenAI exposes the
physical scheduling controls needed around a future integration but not the
public arbitrary non-prefix K/V attachment needed for E2. That boundary is now
implemented as a safe contract and measured as an open gate.
