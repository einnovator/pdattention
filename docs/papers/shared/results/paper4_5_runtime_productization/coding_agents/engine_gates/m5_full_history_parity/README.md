# M5 full-history engine parity gate

This directory contains the direct-engine, ordinary-text control that isolates
PRA-100 correctness from record selection.  Both engines used the same pinned
`mlx-community/Qwen3-4B-4bit` revision
`4dcb3d101c2a062e5c1d4bb173588c54ea6c4d25` at temperature zero on the
16 GiB, 10-GPU-core MacBook Pro M5 running macOS 26.4.1.

| Engine | Exact plain/PRA-100 turns | Source tokens | Newly encoded tokens | Selected-history re-encoding | Selected-history K/V copy |
|---|---:|---|---|---|---|
| mlx-lm 0.31.3 / MLX 0.32.2 | 3/3 | 34, 60, 86 | 34, 16, 16 | 0, 0, 0 | 0, 0, 0 bytes |
| SGLang `gef20fab38` / mlx-lm 0.31.3 / MLX 0.32.2 | 3/3 | 34, 60, 86 | 34, 16, 16 | 0, 0, 0 | 0, 0, 0 bytes |

The byte-exact outputs were `ALPHA`, `BETA`, and `GAMMA` in both arms.  The
nonzero K/V copy is reported separately as canonical lifecycle growth: mlx-lm
reported total copy 6,488,064, 19,169,280, and 26,984,448 bytes; SGLang-MLX
reported suffix grafts of 1,474,560, 1,474,560, and 1,622,016 bytes.  These are
not selected-history materialization bytes.

Both endpoints also passed the lifecycle checks: deleting a session tombstones
its identity and returns HTTP 409 `session_terminated` for stale reuse, while a
fresh session rebuilds its complete source.  The check runs before either
executor evaluates new K/V, and SGLang now rejects cross-tenant session reuse at
the same boundary as MLX.
