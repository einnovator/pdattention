# Exact-token OpenHands three-task tail-90 cohort

> **Post-refactor audit:** these immutable totals reproduce exactly, but the
> historical materializer did not consume the recorded head/tail floors. This
> bundle is evidence for the prompt-pinned pure-recency policy that actually
> ran, not the corrected H2/T4 policy. Fresh corrected runs supersede it for
> policy promotion.

This cohort applies one frozen legacy policy to three locked SWE-bench Verified
tasks: matched token-tail at a nominal 90% budget with immutable prompts and a
causal recency tail. The manifests record protected head 2 and tail 4, but the
historical materializer did not apply those floors. Every
arm uses OpenHands SDK 1.49.2, `qwen3-coder:30b` at digest
`06c1097e...90bca`, the exact corresponding tokenizer, temperature zero,
disabled native condensation, zero semantic-request retries, and a fresh
task-derived workspace.

Provider prompt accounting falls 39.90% and aggregate actions fall by 27.
Own saving measures retirement on each candidate's actual trajectory; paired
saving also includes trajectory contraction and must not be described as pure
selector efficiency.  The tasks are the clustering unit, and the three
identities are non-overlapping.

The result reaches the 30--50% paired-workload target with no observed quality
loss, but the task effects are heterogeneous and there is one OpenHands run per
arm.  It is therefore a strong transfer point, not yet a production-default
accuracy estimate.

The comparison to the submission-guarded mini-swe-agent cohort is controlled
for model digest, tokenizer, tasks, temperature, policy and nominal budget.
Mini-swe-agent preserves 3/3 with 11.68% own and 9.38% paired saving and no
aggregate call change; OpenHands preserves 3/3 with 29.82% own and 43.58%
paired saving and 27 fewer actions.  This difference is agent/workload
specific, not engine specific.  OpenHands carries richer tool schemas and
larger observations, while its selective trajectories also contract more.
Repeat controls are still required before attributing the full gap causally to
policy rather than backend trajectory variance.

`qualification.json` is generated by the task-clustered strict reducer from
the three sibling task qualifications.
