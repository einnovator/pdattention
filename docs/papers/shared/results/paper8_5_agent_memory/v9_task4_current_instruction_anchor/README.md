# Task 4 current-instruction workflow-anchor admission

This bundle records the predeclared Full-only admission test for placing the
task-neutral `coding_minimal_transaction_v7` scaffold on the current genuine
user instruction rather than in the global system prefix.  The treatment is
ingest-time text shared by any later Full/selective pair; it is not a receipt
synthesized from cached history.

The frozen next-action counterfactual had become exactly repeatable (3/3), but
the autonomous result did not transfer.  On `django__django-15741`, Full reached
the 25-call limit, did not submit, and failed official grading.  Its 25 executed
actions contained eight searches, twelve reads, no test, and five other
actions.  The final five actions were three `sed` mutations separated by two
inspections.  The agent never invoked the installed `pra_replace` capability,
never verified the patch, and never submitted it.

This is a negative admission result.  No selective preservation arm was run,
because the matched Full arm did not solve.  It establishes that prompt
salience at one frozen decision is not sufficient evidence for autonomous
workflow control, and that a typed transactional capability must be exposed or
enforced below free-form shell generation if it is to be a reliable portable
mechanism.

The empty `full_current_instruction` directory from the first launch is not
part of this evidence: that launch failed before execution because its log made
the immutable output directory non-empty.  `full_current_instruction_retry01`
is the only executed run represented here.
