# Qwen3-14B model-visible receipt smoke

This directory preserves the first, pre-size-gate diagnostic. Its verbose JSON
receipt format is superseded by the compact, tokenizer-gated
`post_gate/` treatment; the negative result is retained to document why the
gate is required.

This directory compares FULL, whole-group DROP, and the first model-visible
receipt realization on two frozen synthetic decision prefixes. The endpoint was
Ollama 0.30.8 on the M5 16 GB host (`192.168.1.8`), using `qwen3:14b`, the
`Qwen/Qwen3-14B` tokenizer, temperature zero, seed zero, and a 1,024-token
output ceiling. The DROP arms were rerun with the current code so all candidate
artifacts reference the same contemporaneous FULL artifact digest.

| Case / treatment | Valid action | Exact command | Conservative action equivalence | Full / materialized tokens | Observation source / receipt tokens |
|---|---:|---:|---:|---:|---:|
| H1 FULL | yes | yes | yes | 393 / 393 | -- |
| H1 DROP | yes | no | no | 393 / 337 | -- |
| H1 visible resource-map receipt | **no** | no | no | 393 / 501 | 26 / 134 |
| H2B FULL | yes | yes | yes | 354 / 354 | -- |
| H2B DROP | yes | no | no | 354 / 278 | -- |
| H2B visible mutation receipt | yes | no | no | 354 / 472 | 15 / 133 |

Both candidate models remained in the terminal-completion phase. H1 emitted a
natural-language completion without the required command fence, so it is
format-invalid. H2B emitted a valid terminal `echo`, but not the exact FULL
command. These are one-decision next-action diagnostics, not autonomous task
success.

The important systems result is negative: the general JSON receipt is much
larger than either tiny synthetic observation. It expands H1 by 108 tokens and
H2B by 118 tokens relative to preserving the original observation, producing
127.5% and 133.3% materialized retention. A production arm needs a size gate:
use a receipt only when it is smaller than the source observation, otherwise
retain the original observation (or evaluate DROP as a separately labelled
treatment). Resource-map and mutation receipts should therefore be tested next
on genuinely oversized real tool observations, where their fixed metadata cost
can amortize.

The prefix-only audit in `receipt_prefix_audit.json` reconstructs each exact
model request. Both role sequences alternate correctly with no adjacent
assistant messages; every receipt witness ID belongs to the evaluated history
prefix; and no future message content appears in either receipt. The receipt
builder has no future reference-action argument.

Exact invocations used the following treatment-specific options in addition to
the common endpoint/model/tokenizer/generation settings:

```text
H1 receipt: --policy h1_all_branches_consumed_strict --head 0 --tail 0 --budget-fraction 1.0 --search-delay-turns 0 --negative-fallback none --negative-realization visible_receipt --min-decision 7 --max-decisions 1
H1 drop:    identical, with --negative-realization drop
H2B receipt: --policy h2b_verified_write --head 0 --tail 0 --budget-fraction 1.0 --write-delay-turns 1 --negative-fallback none --negative-realization visible_receipt --min-decision 6 --max-decisions 1
H2B drop:    identical, with --negative-realization drop
```

`h1_comparison.{json,md}` and `h2b_comparison.{json,md}` are generated by
`experiments.paper8_5_agent_memory.reduce_frozen_replays` from the raw replay
artifacts in this directory and the adjacent FULL references.
