\begin{abstract}
Large language models commonly expose non-parametric information as a flat prompt, even
when only a small and changing subset is useful. This paper argues for a complementary
interface: \emph{Progressive Retrieval Attention} (PRA), an inference-time sparse
approximation to long-context self-attention. URI references and an implicit bounded prompt
head define logical memory. Long sources are processed as contiguous, model-safe encoding
blocks and sliced into smaller routing chunks. Compact gists index those chunks, while
selected full-detail, layer-native K/V joins direct K/V under the host decoder's attention
operation. The routing representation is therefore not the attention payload, and logical,
requested, resident, and materialized memory are separate quantities. This article records
the original position and updates its implementation gateway to the mature native-KV
design. It labels the earlier adapted cross-attention prototype as historical and summarizes
the evidence subsequently established by the companion series: fragmentation-aware native
transport, bounded execution, positional continuity and RoPE rebinding, distinct semantic
and attention geometries, and exact pretrained-family retrofits. A usable one-shot SDK now
exists for sparse direct-memory workloads, but the work does not yet establish production
  serving economics or a general solution to multi-hop retrieval. Bounded associative discovery,
  evidence-centered materialization, and adaptive effort control now have controlled prototype
  evidence, but reliable entry routing, broad task transfer, and optimized off-device serving
  remain explicit next steps. Corrected layer-placement studies further separate address,
  detail-K/V, routing, and consumer roles: fixed profiles must be calibrated by model, workload,
  materialization, and quality--cost objective rather than inherited as a universal suffix. The
proposal is falsifiable by quality per materialized K/V token, latency, transfer, resident
memory, and content-causal counterfactuals against strong long-context and retrieval baselines.
\end{abstract}

\section{Introduction}

The transformer attention mechanism made it possible for models to condition every token on every earlier token in a sequence \cite{vaswani2017attention}. The same mechanism also created a central systems problem: when a model needs access to many documents, code files, logs, prior decisions, or external knowledge fragments, the simplest interface is to concatenate more text into a longer sequence. Modern long-context systems have stretched this interface dramatically, but a larger window does not by itself solve the problem of \emph{selective use}. If only a small fraction of the context is relevant at any generation step, eager inclusion wastes computation and forces the model to perform implicit search inside an expensive dense attention substrate.

PRA proposes a different working-set rule: \textbf{recent context remains directly visible
at high resolution; older or external context is retained as addressable memory and
disclosed in native-KV detail only when routing predicts it is useful.} Here,
\emph{URI-addressed memory} is external source state identified by a stable URI-like
reference, summarized by compact routing state, and selectively materialized as
layer-native K/V. Explicit handles provide external addresses; displaced prompt history
and streaming rollover are implicit addressable-memory forms that use the same machinery.

Retrieval-augmented generation (RAG) addresses part of this issue by selecting external passages before generation \cite{lewis2020rag,guu2020realm,karpukhin2020dpr}. However, standard RAG often makes a single retrieval decision at the boundary of the model call. The retrieved passages are still inserted as flat prompt text, and the model must consume them whether or not each passage becomes useful later. Agentic systems take the opposite approach: they inspect tool descriptions, issue searches, open files, follow references, and progressively disclose detail only when needed \cite{yao2023react,schick2023toolformer}. This behavior is effective but expensive because the loop is mediated by external actions, repeated model invocations, and hand-designed orchestration.

This paper proposes Progressive Retrieval Attention as a research program for internalizing part of that progressive-disclosure pattern.  Consider a model diagnosing a failing authentication test in a large repository.  Its local prompt can advertise compact handles such as \texttt{<REF\_1>}, whose local reference table maps to \texttt{repo://app/auth\#module}.  The runtime resolves that object, encodes it in bounded contiguous blocks, slices the resulting state into routing chunks, and exposes detailed layer-specific memory only for selected chunks.  The released SDK default is one-shot.  Paper 2.5 separately evaluates bounded memory-to-memory discovery; online recursive decode-resume behavior remains a research target rather than an implied property of one forward pass.

The central question is therefore: \emph{can a model obtain better quality per unit of active context, latency, and memory by treating external information as a progressively materialized context graph rather than an eagerly flattened token sequence?}  The paper develops the vocabulary needed to answer that question, separates architectural, runtime, optimization, and evaluation claims that are often collapsed under ``retrieval,'' and states experiments that could reject the proposal.

\subsection{Scope and Claim Types}

The paper makes an architectural proposal, reports implementation facts, summarizes
historical evidence, and advances hypotheses.  The proposal is the separation among
naming, encoding, routing, admission, and native attention.  The current standalone
implementation establishes bounded source encoding, smaller routing chunks, multi-gist
indexes, exact packed routing, reusable row-isolated caches, implicit-head slicing, one
global materialization budget, and CPU-backed native K/V.  Companion work subsequently
established exact disabled-path pretrained integration and a cross-family research SDK.
These are implementation and controlled-mechanism results.  They do not establish
production throughput, unrestricted benchmark accuracy, recursive retrieval benefit, or
the economics of a serving-optimized deployment.  This distinction is maintained
throughout the paper so that a working mechanism is not mistaken for a general advantage.

\section{Motivation}

\subsection{The Cost of Flat Context}

In a decoder-only transformer with dense self-attention, the attention matrix for a sequence of length $T$ contains $O(T^2)$ pairwise interactions per layer. Efficient kernels and hardware-aware implementations reduce constants, and sparse-attention variants reduce asymptotic or effective cost \cite{beltagy2020longformer,zaheer2020bigbird,kitaev2020reformer,roy2021routing}. Yet a conceptual mismatch remains: many tasks contain large amounts of potentially relevant context but only a small amount of immediately relevant evidence.

Consider a coding task. A repository may contain thousands of files. A developer rarely reads every file before making a change; they inspect a project map, open candidate modules, follow definitions, and read details near the call sites that matter. The useful information is embedded in a hierarchy: repository, package, file, class, method, block. The flat prompt interface collapses that hierarchy into a token sequence. Once collapsed, the model must recover structure through positional and lexical cues that were never designed as stable memory addresses.

The same pattern appears in scientific QA, technical support, legal analysis, and book-length reasoning. The system often knows that a reference exists before it knows whether the reference must be expanded. A long context window encourages eager expansion because the only available memory interface is token inclusion.

\subsection{The Shallowness of One-Shot Retrieval}

RAG retrieves documents or passages and places them in the model context \cite{lewis2020rag}. This often improves factuality and makes model behavior auditable because generated answers can be traced to retrieved evidence. The limitation is that retrieval is usually performed at one granularity and one time. A retriever may return a passage that is too broad, too narrow, or missing the second-hop information required by the question. The generator then has limited ability to request a more specific subdocument without leaving the forward pass and entering an external loop.

Hierarchical retrieval partially addresses this issue by retrieving coarse summaries before detailed chunks, but the retrieved evidence is still usually materialized as prompt text. The generator receives the results of a pipeline rather than participating in a continuous memory-selection process. PRA asks whether part of this selection can be made differentiable, layer-local, or runtime-local.

\subsection{The Expense of Agentic Search}

Agentic systems use tools to search, read, execute, and revise. Their strength is not simply tool use; it is progressive disclosure. A capable agent first consumes compact descriptions and only loads detailed instructions, files, or logs when the task demands them. This style is naturally suited to large workspaces and multi-document tasks. Its weakness is cost and latency. Each search or file read may require a model turn, an external call, and a new prompt construction step.

The motivating question for PRA is therefore not whether agents should disappear. Rather, the question is whether the model/runtime boundary can absorb a lower-level version of progressive disclosure: reference-aware memory expansion during inference, with external agents reserved for high-level planning, verification, and action.

\section{From Flat Context to Context Graphs}

The repository example makes the required abstraction concrete.  Before the model can
route to the authentication implementation, the system needs a stable name for the
object, an explicit relation to any child objects, and a representation compatible with
the layer that will consume it.  This section introduces those three pieces in that
order.  A useful way to keep them straight is to distinguish three levels of detail.
The handle is an address, the routing gist is a small representation used to decide
whether a chunk looks useful, and the token-level K/V is the evidence the decoder can
actually read.  Moving between these levels is the ``progressive'' part of PRA.

\subsection{Reference Handles}

A \emph{reference handle} is a lightweight token or latent marker that names an external memory object without expanding it immediately.  It plays the role of a typed
pointer in the prompt: the pointer says where the object can be found, but it is not a
summary of the object and does not consume the object's full token budget.  In the
simplest textual form:

\begin{center}
\texttt{<REF\_1>} $\rightarrow$ \texttt{repo://app/auth\#module}
\end{center}

The handle is paired with a local reference table containing at least an identifier,
token, and URI, with optional summary and metadata.  The local table supplies the
binding: \texttt{<REF\_1>} has meaning only in the example or object that advertises it.
Child edges exist only through this explicit table; URI-prefix similarity is not
sufficient to create graph structure.  The prompt can therefore advertise a possible
source without pretending that the source has already been read.

\subsection{URI-Addressed Memory}

PRA assumes that external memory can be addressed by URIs. The URI is the stable identity
of source state, not its routing gist or transported K/V. The scheme may denote local
memory, files, repository objects, search results, database rows, or runtime objects:

\begin{center}
\texttt{mem://manual\#installation.cuda.vllm}
\end{center}

The anchor fragment after \texttt{\#} is not merely a byte offset. It can encode semantic hierarchy: document, section, subsection, paragraph, function, class, or trace event. URI addressing gives the runtime a stable object to cache and gives the model a compact symbol for a potentially large subtree of context.

\subsection{Prompt History as an Implicit Reference}

Explicit handles are not the only way an object can enter the context graph.  Once a
prompt exceeds the direct-token budget $D$, its older prefix can be reclassified as a
request-local object while the most recent suffix remains in causal self-attention.  For
token sequence $x_{1:N}$ with $N>D$, the implemented split is exact:
\begin{equation}
z_{\mathrm{head}}=x_{1:N-D},\qquad x_{\mathrm{direct}}=x_{N-D+1:N}.
\end{equation}
The head is registered under \path{pra://implicit/prompt/head} (shown in diagnostics as
\texttt{\#\_\_head}), encoded once as causal history, sliced into independently routable
native-K/V chunks, and routed through the ordinary PRA memory path.
No visible marker is inserted into the suffix, and no decode--re-encode round trip changes
the token identities.  The reserved URI is scoped to one batch row and one request; a new
request replaces it rather than inheriting stale prompt history.

This mechanism turns chronological displacement into the same named-object interface used
for external documents.  It is not equivalent to keeping the entire prefix in dense
self-attention: the head becomes non-causal memory after it has been observed, and only
selected chunks are transported.  The implementation also retains \texttt{truncate} and
\texttt{error} overflow policies. During generation, expired routing-sized prefixes of
the direct suffix are appended to the same implicit object and re-encoded through the
bounded source path. This correctness-first rollover rebuilds the head cache;
incremental append remains future systems work.

\subsection{Logical Context Under a Native Bound}

PRA separates the size of its logical address space from the maximum context processed by
the underlying model in any one operation:
\begin{equation}
L_{\mathrm{logical}} \gg L_{\mathrm{model,max}}
\ge L_{\mathrm{encode}} > L_{\mathrm{route}}.
\end{equation}
Long sources are encoded in bounded, optionally overlapping blocks. Context-only overlap
is discarded before each block's native K/V is sliced into smaller routing chunks. After
routing, all candidate sources share one score-ordered whole-chunk admission budget:
\begin{equation}
L_{\mathrm{direct}}+L_{\mathrm{materialized}}+L_{\mathrm{reserve}}
\le L_{\mathrm{model,max}}.
\end{equation}
This does not make the base model natively support arbitrary context. It exposes a larger
logical context while keeping each encoding and attention operation within a configured
native limit.

\textbf{Logical context may exceed native model context, but no underlying model operation
may exceed the configured native limit.} This is a runtime contract, not a claim that the
base model's positional or attention machinery has been enlarged.

\subsection{Recursive Anchors}

\textbf{This subsection describes the next-stage architecture, not the current one-shot
algorithm.} Many references are best exposed recursively.  A root object may advertise child
anchors, and those child objects may advertise more specific anchors:

\begin{center}
\texttt{mem://manual\#root}
$\rightarrow$
\texttt{mem://manual\#installation}
$\rightarrow$
\texttt{mem://manual\#installation.cuda}
\end{center}

Recursive anchors would turn context into a traversed graph rather than a bag of chunks.
Expansion must be child-first and bounded by shared depth, child, reference, token, latency,
and byte budgets. Build states must prevent partially encoded cyclic entries from becoming
searchable, while content/model/tokenizer/routing fingerprints protect cache identity. The
current runtime can resolve bounded child tables during cache construction, but it does not
yet use generated evidence to perform online decode-resume expansion. Paper 2.5 evaluates
bounded associative discovery over a frozen memory graph, but it does not turn recursive
page faults into a production decoding policy.

\subsection{Layer-Specific Memory Cache}

If an external fragment is encoded into memory for attention, the representation should respect the transformer's layer structure. A key/value pair computed for one layer is not generally interchangeable with another.  In practical terms, PRA does not encode a
chunk once and hand the same vector to every layer.  It runs the chunk through the same
model stack used by the prompt and captures the representation appropriate to each configured
depth.  Four sets must be named separately: address layers retain compact states, detail layers
retain full source K/V, routing layers score memory, and consumer layers admit selected K/V to
attention.  PRA therefore uses a role-aware layer-specific memory cache:

\begin{equation}
\mathrm{cache}[u,c,\ell] = (K_{u,c,\ell}, V_{u,c,\ell}, G^K_{u,c,\ell},G^V_{u,c,\ell}),
\end{equation}

where $u$ is a URI, $c$ a deterministic chunk, $\ell$ a transformer layer, $(K,V)$ is present only
for $\ell\in L_{\mathrm{detail}}$, and $G^K,G^V\in\mathbb{R}^{G_c\times d}$ are paired contextual
address gists for $\ell\in L_{\mathrm{addr}}$.  Mean, last-token, reference-end, and GRU modes produce $G_c=1$; k-means, prototype, self-organizing-map, and hybrid modes may retain several local regions.  A gist is an index entry, not a compressed replacement for the
chunk: it is cheap to compare with a query, while the full K/V preserves token-level
detail after selection. This distinction matters because lower layers may encode lexical and syntactic information while higher layers may encode task-specific abstractions. Raw token embeddings or document summaries are not substitutes for layer-specific routing and attention memory.

\section{Progressive Retrieval Attention}

\subsection{Conceptual Computation}

Return to the authentication example.  Local self-attention relates the test tokens and
the code already present in the prompt.  The memory branch answers a different question:
given the current diagnosis, which advertised module chunks should become additional
evidence at this layer?  The computation below separates the cheap ranking operation
from the more expensive attention over detailed evidence.  Operationally there are two
phases.  A preparation phase resolves each advertised URI, partitions its content, and
builds layer-specific chunk memories.  A use phase lets the live prompt query the small
chunk gists, materializes only the selected K/V, and fuses the resulting memory read with
ordinary causal self-attention.

Let $X \in \mathbb{R}^{T \times d}$ contain the $d$-dimensional hidden states for $T$
local tokens at layer $\ell$.  Standard causal self-attention first projects these states
into queries $Q$, keys $K$, and values $V$.  Each head has width $d_h$, and $M$ masks
future positions:

\begin{equation}
\mathrm{SelfAttn}(X) =
\mathrm{softmax}\left(\frac{QK^\top + M}{\sqrt{d_h}}\right)V,
\end{equation}

The output mixes values from preceding local positions according to query--key
compatibility.  A memory-consuming layer preserves that path and adds memory selected from a cache.
For routing, it uses the projected query at the most recent valid position, merges its
heads into $q_{t,\ell}$, and compares it with every projected-key gist
$g^K_{u,c,\ell,j}\in G^K_{u,c,\ell}$ for chunk $c$ of object $u$:

\begin{align}
q_{t,\ell} &= \operatorname{mergeheads}(XW_Q^{(\ell)})_t,\\
a_{u,c,\ell,j} &= \cos(q_{t,\ell},g^K_{u,c,\ell,j}),\\
a_{u,c,\ell} &= \operatorname{Agg}_{j=1}^{G_c}a_{u,c,\ell,j}.
\end{align}

The default aggregation is maximum; mean and log-sum-exp are alternatives.  URI-level
gist sets can likewise select references before chunk scoring, so ``reference-first'' is
a real two-stage route rather than a relabeling of flattened chunk scores.  The aggregate
score $a_{u,c,\ell}$ ranks small routing representations rather than the
full chunk.  Hierarchical routing aggregates chunk scores to select at most $k_r$
references, then independently selects at most $k_c$ chunks inside each selected
reference.  Content-derived gists are the default.  Summaries, when available, may
replace, augment, or compete with content scores under an explicit policy, but missing
summaries fall back to content.  Let $\mathcal{A}_{t,\ell}$ be the selected
reference--chunk pairs.  This routing score answers ``which drawers should be opened?'';
it is not an attention weight over the evidence inside a drawer. Canonical transport
prepends selected historical keys and values to the local keys and values:

\begin{equation}
\mathrm{PRA}_{\ell}(X)=W_O^{(\ell)}\,
\mathrm{softmax}\!\left(
\frac{Q^{(\ell)}[K_{\mathcal A,\ell};K_{\rm local}^{(\ell)}]^\top}
{\sqrt{d_h}}+M_{\rm causal}\right)
[V_{\mathcal A,\ell};V_{\rm local}^{(\ell)}].
\end{equation}

Here $K_{\mathcal{A},\ell}$ and $V_{\mathcal{A},\ell}$ concatenate full layer-$\ell$
token memory from selected chunks only. Memory and local positions compete in one
normalization, and the layer uses its existing $W_O$; there is no memory scale or new
transport projection. In
the running example, the gist may select the password-validation chunk, but the decoder
receives that chunk's token-level keys and values and can assign different attention
weights to its individual tokens.  Routing representations are therefore cheap
selectors, not compressed substitutes for transported evidence.

\textbf{Routing gists are selectors; selected chunks materialize full native token-level
K/V.} Consequently gist count, stored source K/V, transferred K/V, and active attention
K/V are different accounting quantities.

The central research problem is selection: how should $\mathcal{A}_{t,\ell}$ be chosen? Possible triggers include contextual gist similarity, attention to explicit reference-token positions, uncertainty in the next-token distribution, learned gates, or runtime policies that trade accuracy against latency. Reference ranking, chunk ranking, and materialization must remain separately measurable.

\subsection{PRA as Architecture, Runtime, and Research Program}

The term PRA is intentionally broader than one neural module.  As an
\emph{architecture}, it denotes attention layers that consume external reference memory
through native K/V injection. Optional adapted modes may use cross-attention or adapters,
but they are secondary variants rather than the definition of PRA.
As a \emph{runtime}, it includes the resolvers, caches, URI stores, expansion policies,
and schedules that decide when and how the memory is constructed.  As a \emph{research
program}, it includes the benchmarks, ablations, scaling studies, and analyses needed to
test demand-driven context expansion.

These scopes support different conclusions.  A standalone prototype can validate cache
construction and attention mechanics without showing readiness for a production-scale
pretrained model.  Runtime experiments can study scheduling and K/V reuse without
settling how to train the selector.  Scaling studies can ask which task distributions
benefit from context graphs without committing to one resolver or cache implementation.
The following commitments keep those conclusions separable.

\section{Conceptual Commitments}

PRA is most useful as a research frame when several concerns remain separate. Collapsing them produces systems that may work but cannot be interpreted.

\subsection{Naming Is Not Materialization}

A reference handle states that a memory object exists and can be addressed. It does not imply that the object's text, embeddings, or K/V tensors have already been loaded. This distinction allows a runtime to expose a large logical context graph while maintaining a small active physical context. It also supports late binding: two deployments may resolve the same logical URI through different stores, permissions, or freshness policies.

The separation creates a useful sequence of representations:

\begin{equation}
\mathrm{handle} \rightarrow \mathrm{metadata} \rightarrow
\mathrm{optional\ summary} \rightarrow \mathrm{text/chunks} \rightarrow
\mathrm{layer\ memory}.
\end{equation}

Each transition has a cost and can be denied, cached, audited, or deferred. Progressive disclosure is therefore not merely truncation; it is movement through explicit levels of materialization.

For a reader following one reference end to end, the sequence is concrete.  The prompt
first carries a symbolic address.  Resolution turns that address into an authenticated,
versioned object.  Encoding creates small layer-specific gists plus detailed token K/V.
Routing scores the gists, and only then does memory attention consume selected K/V.  A
system may prepare some of these representations eagerly or retrieve them from a cache,
but the logical boundaries remain the same.

\subsection{Selection Is Not Transport}

Selecting a URI and transporting its representation into a model are different operations. Selection may use lexical retrieval, vector similarity, explicit handle positions, learned gates, uncertainty, or an oracle. Canonical transport uses native layer K/V; prompt concatenation, cross-attention, and adapters are comparison transports. An experiment that changes both at once cannot determine whether a gain comes from finding better evidence or from presenting the same evidence through a better neural interface.

PRA evaluations should first bypass selection: restoring all historical native K/V must match full self-attention when positions and masks are equivalent. Oracle sparse selection then measures the cost of omitting K/V, and only afterward should routed, shuffled, and learned selection be evaluated. Cross-attention remains a separate adapted-transport comparison.

This sequence supports a quantitative error decomposition. The gap from full
SelfAttention to native all-memory measures transport, partition, and position cost; the
gap from all-memory to sparse oracle measures sparsification cost; and the gap from oracle
to routed memory measures selection cost. For condition $c$, Recovered Context Benefit
is
\begin{equation}
\mathrm{RCB}_c =
\frac{L_{\rm tail}-L_c}{L_{\rm tail}-L_{\rm full}}.
\end{equation}
RCB asks how much of the predictive advantage of dense context is recovered over a local
tail. It is undefined when dense context offers negligible advantage and is not clipped
when memory is harmful or outperforms the dense baseline. The companion systems quantity
is active token-K/V fraction,
$(T_{\rm local}+T_{\rm retrieved})/(T_{\rm local}+T_{\rm displaced})$; routing gists are
reported separately. The scaling thesis is supported only if RCB remains high while this
active fraction falls, not merely when a PRA loss is lower than an unrelated baseline.

The same separation applies inside selection. Reference ranking answers which addressable objects remain candidates; chunk ranking answers which portions of those objects are materialized. Independent budgets are necessary to prevent a prolific reference from consuming every chunk slot. Reported cache size, selected gist count, and transported token count are different quantities and should never be used interchangeably.

\textbf{Active K/V is not total resident K/V.} Sparse attention becomes a GPU-capacity
benefit only when unselected payload can remain off device, be evicted, or be shared without
materialization.

\subsection{Implementation Invariants}

The mature implementation is easier to reproduce when its invariants are stated before its
optimizations. First, when PRA is disabled or has no selected memory, the host attention path
is bypassed rather than approximately reconstructed. The standalone tests require the native
history replay to match full causal attention when positions and masks are equivalent;
pretrained-family adapters additionally require exact PRA-off logits, hidden states,
generation, and tested cache behavior. Exactness applies to the named controls, not to sparse
memory as an approximation of an omitted dense context.

Second, the compact index and attention payload have different jobs. A routing gist may be a
pooled hidden state, projected key, or learned semantic vector. It identifies a URI and routing
chunk. Once selected, the payload is the host layer's full-detail native K/V, including its
head layout, dtype, positional treatment, and cache convention. Canonical PRA introduces no
separate memory output projection or residual scale; the historical cross-attention mode does.

Third, accounting follows the lifecycle rather than one ambiguous ``context fraction.'' Let
$T_{\rm logical}$ be all addressable source tokens, $T_{\rm requested}$ the tokens belonging to
selected references or parents, and $T_{\rm materialized}$ the K/V tokens admitted to an active
operation. Then
\begin{equation}
0 \le T_{\rm materialized} \le T_{\rm requested} \le T_{\rm logical},
\end{equation}
but equality is not assumed. Routing gists, host-resident K/V bytes, transferred bytes, padded
attention allocation, and attended physical K/V tokens are reported separately. This prevents
a logical selection rate from being presented as a physical memory saving.

Finally, the lifecycle remains bounded. Every source encode, direct-plus-memory attention
operation, resolver expansion, transfer, and cache admission is subject to explicit token,
byte, depth, identity, and isolation constraints. CPU or off-device residency reduces accelerator
capacity only when selective transfer keeps unselected payload off the active device; it does
not erase encoding, storage, or communication cost.

\subsection{Logical Isolation Must Survive Physical Batching}

Each sequence has a logical memory address space even when kernels share physical tensors.
Two rows may even use the same URI string for different content; the row-local reference
table decides what that name means.  An efficient implementation can still run the
prompt as one batch by keeping a private cache namespace for each row, routing row $i$
only against namespace $i$, and masking padded memory positions. Correct batching may
evaluate each row independently, pad one masked rectangle, or group rows into deterministic length buckets. These execution plans are equivalent only if empty rows receive an exact zero memory residual, outputs return to original order, and one row's cache cannot influence another row's logits. Padding allocation and bucket count are systems metrics, not semantic changes to routing.

\subsection{Language Ability Is Not Reference Adaptation}

Adding a memory path can improve a reference-formatted task while damaging ordinary language modeling. Conversely, freezing the local model can guarantee preservation while limiting adaptation. The relevant object is therefore a two-dimensional outcome: reference-task improvement and local-task retention. A useful method should report both, including the exact trainable parameter groups.

This distinction motivates staged optimization. First establish that each architecture learns ordinary language. Then initialize from the matching checkpoint and train only newly activated reference-specific modules. Finally, compare joint fine-tuning under a mixed plain/reference curriculum. Preservation obtained by freezing is a property of the optimization policy, not proof that an architecture is intrinsically immune to forgetting.

\subsection{Memory Identity Requires Isolation}

URI identity is part of the conditioning state. If a batched implementation combines references from unrelated examples without a corresponding mask, it changes the task and can leak evidence across samples. The standalone implementation exposed this issue directly: a batch-union cache made within-batch shuffling ineffective. Correctness required a cache per example. Efficient PRA runtimes must preserve the same logical isolation through cache indices or attention masks even when physical storage and kernels are shared.

\section{Virtual Memory for Transformers}

Virtual memory changed computing by separating the address space visible to a program from the finite physical memory resident at a given moment. Pages are named independently of their current location, loaded lazily, cached while useful, and evicted under pressure. Working-set theory connects recent access behavior to resource allocation rather than pretending that every address must remain resident \cite{denning1968workingset}. Foundation-model context has an analogous tension: the logical information relevant to a task can be far larger than the token and K/V memory physically active during one decoding step.

PRA proposes a \emph{virtual context space}. URIs and anchors play the role of stable logical addresses. Resolved text or structured objects are backing-store content. Encoded layer-specific K/V entries are resident pages. Selection or gating acts as an admission policy. A missing selected representation creates a context fault that triggers resolution and encoding. The active reference cache approximates a working set, while eviction and reuse determine whether the abstraction saves end-to-end cost.

\subsection{PRA as Semantic Virtual Memory}

The target is not literal infinite context.  It is a systems regime in which logical context is
much larger than physical active context:
\begin{quote}
\emph{Logical addressable context can grow far beyond the model's native attention window and
GPU-resident K/V capacity without requiring all logical context to be simultaneously materialized
in attention.}
\end{quote}
We call this \emph{effectively unbounded logical context}, \emph{externally backed logical
context}, or \emph{demand-loaded context}.  All three phrases remain conditional on finite
backing storage, an executable lookup policy, bounded native operations, and measured systems
cost.  They do not imply mathematically infinite memory, constant lookup time, or quality that is
independent of corpus scale.

The target GPU footprint is approximately
\begin{equation}
M_{\mathrm{GPU}} \approx M_{\mathrm{model}} + M_{\mathrm{head}}
+ \sum_{\ell\in L_{\mathrm{consume}}}M_{\mathrm{active}}^{(\ell)}
+ M_{\mathrm{runtime}},
\end{equation}
where $L_{\mathrm{consume}}$ is the calibrated set of consumer layers.  The intended signature is that
$M_{\mathrm{active}}$ depends primarily on the task/query working set, not on every token in the
logical store.  Routing and index work may still grow with the store, CPU/reference memory grows
with retained content, and a poor policy may broaden the working set.  Scale-independent physical
memory is therefore an experimental target, not a present claim.

Later results refine the early ``chunk equals page'' analogy into three granularities:
\begin{equation}
G_{\mathrm{encode}} \neq G_{\mathrm{search}} \neq G_{\mathrm{materialize}}.
\end{equation}
$G_{\mathrm{encode}}$ is the context used to create meaningful representations;
$G_{\mathrm{search}}$ is the conceptual routing or native-graph node; and
$G_{\mathrm{materialize}}$ is the actual native-K/V interval loaded into active attention.
Coarser encoding can contextualize finer search nodes, while physical materialization may later
union or window several selected nodes.  Paper 2.5 shows why the separation matters: finer search
nodes can reduce conceptual payload while also removing useful associative edges.

Sparsity also has a layer axis.  PRA may be sparse over
\begin{equation}
\text{memory regions}\ \times\ \text{token/K/V detail}\ \times\
\text{consumer layers}.
\end{equation}
Paper 2 establishes selective pretrained-model consumer paths.  Corrected Paper-3 replay and
Paper-4.5 cross-model calibration now show why neither ``always all layers'' nor ``always the last
eight'' is a stable rule.  Placement depends on the model, workload, physical materialization,
transport, and optimization objective.  All eligible consumers remain a conservative
reference-correctness fallback when sparse consumption has not been validated; it is not a claim
of quality optimality.

\subsection{A Progressive Research Program for Demand-Loaded Neural Memory}
\label{sec:program-roadmap}

demand---does not reduce to one retrieval mechanism.  It decomposes into addressing and transport,
coordinate correctness, pretrained-model integration, memory discovery and traversal, physical
K/V disclosure, adaptive control and retry, learned memory consumption, scaling laws, production
serving, and synthesis with adjacent approaches.  The sequence emerged partly through negative
results.  Better graph traversal did not automatically improve answers; smaller, correctly gathered
materializations did not uniformly improve likelihood; replaying memory at every layer could harm
behavior; and reducing K/V in a Python prototype did not automatically reduce time to first token.
These are independently failing boundaries, not interchangeable meanings of ``retrieval.''

The program's compact vocabulary is
\emph{address $\rightarrow$ discover $\rightarrow$ disclose $\rightarrow$ assimilate
$\rightarrow$ control $\rightarrow$ scale $\rightarrow$ serve}.
\textbf{Address} names and governs external memory.  \textbf{Discover} identifies relevant
conceptual memory.  \textbf{Disclose} determines which native K/V detail becomes physically active.
\textbf{Assimilate} asks whether the transformer productively uses that state.  \textbf{Control}
allocates effort and decides when to retry.  \textbf{Scale} measures how quality and cost change with
model and logical-memory size.  \textbf{Serve} tests the architecture under actual batching, cache,
transfer, concurrency, and distribution constraints.  Tables~\ref{tab:vm-status-a} and
\ref{tab:vm-status-b} track implementation and evidence for the virtual-memory components; this
roadmap instead assigns the scientific questions and handoffs.

The decomposition is methodological rather than publication-driven: experiments repeatedly show
that transport, discovery, physical disclosure, functional consumption, adaptive control, scaling,
and serving can fail independently.  Treating them separately enables causal experiments and
prevents a successful result at one layer from being misinterpreted as success of the complete
system.  Successful stages may eventually motivate unnumbered branches on learned memory
representations, continual write and consolidation, neural modules, or adaptive cognitive
architectures; none is claimed as an established result or committed publication.

\subsection{Address Spaces, Protection, and Lifetime}

A useful virtual context address is more than a string. It should identify scheme, authority, object, semantic anchor, version, tenant, and access policy. Two identical texts with different provenance may not be interchangeable; one URI whose content changes over time should not silently reuse stale K/V. Cache keys may therefore require a tuple such as

\begin{equation}
(u, v, \ell, m, \theta, p),
\end{equation}

where $u$ is URI, $v$ content version, $\ell$ layer, $m$ model identity, $\theta$ relevant encoder parameters, and $p$ policy domain. Cache lifetime can range from one sequence to a user session, repository revision, model deployment, or immutable corpus version. Longer reuse improves amortization but increases freshness and revocation risk.

Permissions must be enforced before resolution and again when resident memory is shared. A model should not infer a protected reference because another tenant populated the same physical cache. Logical address spaces and attention masks must survive batching, deduplication, paging, and distributed placement.

\subsection{Page Faults and Progressive Disclosure}

A conventional page fault is generated by an exact address access. A model's ``context fault'' is less crisp: it may be inferred from explicit handle attention, uncertainty, a learned router, or a runtime policy. False negatives omit evidence; false positives waste resolution and encoding. This turns fault prediction into a joint learning-and-systems problem. Recursive anchors further resemble multi-level page tables only loosely: following a child changes semantic granularity rather than merely translating an address.

\subsection{Where the Analogy Breaks}

CPU pages are intended to preserve exact program semantics regardless of placement. Neural memory is approximate, content-dependent, and transformed by model parameters. Loading a document into K/V does not guarantee that the model will use it correctly. Attention can blend untrusted entries, positional semantics may matter, and encoding may be more expensive than transport. The virtual-memory analogy is therefore valuable for identifying address, isolation, admission, working-set, and eviction problems; it is not evidence that operating-system policies can be copied unchanged.

Classical translation starts from an exact virtual address and follows deterministic page tables.
PRA translation is learned and content-addressed:
\begin{equation}
\text{question} \rightarrow \text{semantic candidates} \rightarrow
\text{associative expansion} \rightarrow \text{materialized native K/V}.
\end{equation}
It therefore has semantic failure modes with no direct analogue in ordinary virtual memory: a
wrong root, distractor competition, a missing native edge, over-broad activation, or a
miscalibrated controller.  Conversely, PRA can propose content-related neighbors and perform
associative prefetch rather than waiting for an exact address.  That extra capability is useful
only when its recall, false activation, and physical cost are measured together.

\subsection{Decisive Virtual-Memory Scaling Experiment}

The unresolved systems claim requires a direct scaling experiment, not extrapolation from small
fixed-$k$ curves.  Construct matched logical memories of 32K, 128K, 512K, 2M, and at least 8M
tokens while holding task families and evidence requirements constant.  At every scale report:
answer quality; root and evidence recall; active native-K/V tokens and bytes; peak HBM;
CPU/reference-store memory; routing, index, and graph-search latency; interval-gather and H2D
latency; TTFT; TPOT; and, when the runtime supports it, throughput and concurrency.  Dense native
context, sparse attention, RAG, and agentic search should receive matched task and hardware
conditions.

The desired signature is stable matched-task output quality while logical memory grows from 32K
to 8M+ tokens and the GPU native-K/V working set remains approximately bounded by a
task-dependent budget.  Search or index latency may grow, and backing-store memory should grow;
the narrower hypothesis is that GPU attention working-set cost does not grow linearly with total
logical context.  Failure to preserve recall, quality, or bounded active K/V at scale would narrow
or reject the virtual-context thesis.  Until this experiment exists, PRA does not provide
scale-independent physical memory, constant-cost page faults, or reliable routing at arbitrary
memory size.

\section{Current Architecture and Reference-Memory Lifecycle}

A PRA runtime is a lifecycle rather than a single retrieval call. The current one-shot path is:

\begin{enumerate}[leftmargin=*]
\item \textbf{Advertise}: expose handles, summaries, types, provenance, and access policy.
\item \textbf{Select references}: rank candidate handles for a sequence, position, layer, or decoding interval.
\item \textbf{Resolve}: map selected URIs to immutable or versioned content.
\item \textbf{Encode}: process source text as bounded contiguous blocks and retain host-native,
layer-specific K/V; context-only overlap is not a separately addressable payload.
\item \textbf{Slice and index}: divide encoded K/V into smaller routing chunks and derive one or
more compact gists without replacing the detailed payload.
\item \textbf{Route}: rank reference and chunk identities against the compact index.
\item \textbf{Admit and transfer}: choose whole chunks under one native-operation budget and
move only selected K/V from CPU or other backing storage when needed.
\item \textbf{Attend}: allow authorized sequence positions and layers to consume the memory.
\item \textbf{Reuse or evict}: retain useful entries across tokens or requests, or release them under pressure.
\item \textbf{Audit}: record which version, URI, layer, and policy influenced the output.
\end{enumerate}

This lifecycle suggests a cost objective. For task quality $Q$, prompt tokens $T_p$, encoded reference tokens $T_r$, latency $L$, and active cache bytes $B$, a system should be compared on a frontier such as

\begin{equation}
\max Q \quad \text{subject to} \quad
c_p T_p + c_r T_r + c_l L + c_b B \leq C.
\end{equation}

The constants depend on hardware, cache reuse, and service-level objectives. PRA is not successful merely because it shortens the visible prompt. Reference encoding that is repeated for every request may cost more than eager context. The economic case depends on selective admission, amortized reuse, or better quality under a fixed resource budget.

\section{Layer Roles and Calibrated Profiles}
\label{sec:layer-profiles}

\subsection{Four roles, not one ``PRA layer'' set}

Depth participates in four different operations:
\begin{align}
L_{\mathrm{addr}} &:\ \text{retain compact states that can address memory},\\
L_{\mathrm{detail}} &:\ \text{retain full source-native K/V for possible page-in},\\
L_{\mathrm{route}} &:\ \text{execute reference or chunk selection},\\
L_{\mathrm{consume}} &:\ \text{join selected memory K/V to direct attention}.
\end{align}
These sets may overlap but are not synonyms.  An address-only layer can retain a cheap gist without
retaining token-level detail.  A route-once layer can choose identities later consumed by several
layers.  A detail layer can remain dormant until another layer's routing decision materializes its
K/V.  A consumer requires corresponding detail K/V, so
$L_{\mathrm{consume}}\subseteq L_{\mathrm{detail}}$ in the current runtime.  This vocabulary
replaces the ambiguous phrase ``PRA layers'' throughout the series.

The stable implementation invariant is
\begin{equation}
\text{correct positional transport}
+\text{coherent materialization}
+\text{sufficient consumer depth}.
\end{equation}
None of the three terms repairs another.  A strong layer profile cannot rescue K/V replayed in an
incompatible RoPE frame.  Exact evidence cannot rescue a consumer topology that amplifies
interference.  Conversely, all-layer consumption can be transport-correct while lowering quality.

\subsection{What the current evidence supports}

The corrected Paper-3 retrospective fixes source-offset query positions and holds oracle identity
and native transport constant while varying $L_{\mathrm{consume}}$ on Qwen3-0.6B
\cite{simao2026materialization}.  On 16 held-out identities per workload, the last 20 of 28 layers
maximize mean gold-answer log probability for both MuSiQue and 2Wiki.  A last-eight band retains
1.190 and .949 nats of gain at 40\% of the last-20 layer-token cost.  Early-four and evenly spaced
profiles are harmful.  All-layer replay reaches $+.957$ on MuSiQue but $-2.290$ on 2Wiki, so it is
not a quality ceiling.  Crossing exact cores, local windows, selected records, and whole parents
also shows that a materialization result can change with consumer topology.

Paper~4.5 then tests the same profile contract as a runtime calibration problem
\cite{simao2026runtime}.  In direct-prefix/reference parity checks, Qwen3-0.6B and the tested
Llama-3.2-1B mirror require all eligible layers for the conservative balanced profile; short suffixes
lose quality.  Gemma-3-1B's four globally attentive layers likewise require all four in the tested
topology, while its local-attention integration remains partial.  Qwen's last-24 suffix has the best
answer log probability in its small calibration cohort but unacceptable full-logit drift, so it is
recorded as a research quality-max candidate rather than the SDK default.  The evidence therefore
supports coexisting workload, family, materialization, and objective dependence.  It does not yet
establish a size law.

\subsection{Profile objectives and calibration method}

The runtime exposes four named objectives.  \textsc{Reference-correctness} activates all eligible
consumers as the conservative fallback when no sparse profile is validated.  \textsc{Quality-max}
selects the held-out quality optimum, even when expensive.  \textsc{Balanced} selects a point on
the measured quality--K/V--compute frontier.  \textsc{Economy} minimizes active state under an
explicitly accepted quality floor.  A routing/discovery profile, task-composition profile, and
answer-generation profile may eventually differ, but that role-specific optimization remains a
hypothesis rather than a default.

The canonical calibration procedure is:
\begin{enumerate}
\item verify native prefix/reference parity and positional provenance;
\item freeze the workload, materialization policy, model, tokenizer, and revision;
\item sweep normalized contiguous consumer suffixes;
\item compare sparse and contiguous profiles at matched layer counts;
\item measure output quality, residual divergence, active K/V, compute, and latency;
\item construct the Pareto frontier and select quality-max, balanced, and economy candidates;
\item validate candidates on identities not used for selection;
\item store the result in a versioned registry with user overrides and a conservative fallback.
\end{enumerate}
Profiles cannot be compared across model revisions without provenance.  Fixed calibrated profiles
are the default because adaptive predictors elsewhere in the series have often underperformed
well-chosen fixed policies.  Dynamic layer selection requires its own held-out evidence.

The standalone study remains complementary.  It compares four local consumers, four memory
consumers, and a two-plus-two hybrid under training.  In its five-seed follow-up, frozen-path
reference loss is 4.6720 for full consumption and 4.7296 for hybrid consumption.  The hybrid uses
fewer trainable memory projections and trains faster, but one tiny model and an unlearned selector
cannot determine a placement law.  The next scaling test should compare optimal normalized
consumer depth against model depth and parameter count while stratifying lexical, syntactic,
relational, and answer-generation workloads.

\section{Relationship to Existing Work}

PRA draws mechanisms from several mature lines of work. The comparison is organized by
\emph{which resource changes}: prompt text, token connectivity, positional range, retained
K/V, persistent state, retrieved neural state, or the external action boundary. This framing
narrows the novelty claim to an access contract that combines stable names, a compact semantic
index, selective native-K/V materialization, and a bounded lifecycle. None of those ingredients
is claimed as individually new.

\subsection{Retrieved Text and Latent Retrieval}

RAG, REALM, and dense passage retrieval select external text, usually before generation, and
let the generator encode the selected passages in its current prompt
\cite{lewis2020rag,guu2020realm,karpukhin2020dpr}. Their changed resource is the input text.
This preserves a simple model interface and lets retrieval scale independently, but selected
text still incurs prompt encoding and dense participation once inserted. PRA can use the same
retriever to choose candidate URIs, then route smaller chunks and consume cached layer-native
state rather than append every selected passage.

Latent retrieval moves selection closer to model representations. The $k$NN-LM interpolates
the model distribution with neighbors from a hidden-state datastore; Memorizing Transformers
retrieve prior token memories; and RETRO retrieves text chunks for learned generator-side
conditioning \cite{khandelwal2020knnlm,wu2022memorizing,borgeaud2022retro}. These methods and
PRA all expose non-parametric information during inference. Their memory values and fusion
rules differ: PRA retains URI identity and provenance, uses compact vectors only for search,
and presents selected full-detail native K/V to ordinary attention. It does not interpolate a
neighbor token distribution or require RETRO's trained cross-attention architecture.

\subsection{Sparse, Local, and Block Attention}

Longformer, BigBird, Reformer, and Routing Transformer change token-to-token connectivity
inside an admitted sequence through local windows, global tokens, hashing, or content routing
\cite{beltagy2020longformer,zaheer2020bigbird,kitaev2020reformer,roy2021routing}. These methods
answer how a long sequence should interact after it is present. PRA first asks which external
state should enter the active operation. The approaches are complementary: a sparse or block
kernel could execute direct-plus-materialized K/V after PRA admission.

Landmark Attention similarly gives a long sequence coarse random-access landmarks
\cite{mohtashami2023landmark}. A PRA gist has a related indexing role, but it belongs to a
separate addressable cache and is not the evidence consumed by attention. The selected routing
chunk materializes its detailed K/V payload. This routing--payload distinction is the central
difference.

\subsection{Long-Context Position and Sequence Range}

Context-extension methods change the length over which one model invocation can preserve useful
token interaction. Transformer-XL adds segment recurrence and relative positions; Position
Interpolation and LongRoPE extend the operating range of positional geometry
\cite{dai2019transformerxl,chen2023positioninterpolation,ding2024longrope}. Their strength is
continuous access to a large admitted sequence. PRA does not enlarge the host model's native
limit. It constructs logical scope from model-safe encoding blocks and admits a bounded subset
to each operation. A longer native window can therefore improve PRA's encoding and direct
context while leaving the logical-versus-active separation useful.

\subsection{KV Retention, Compression, Eviction, and Quantization}

H$_2$O and SnapKV evict or retain decoding-cache tokens, ClusterKV merges cache state in a
semantic space, and KIVI reduces bytes through asymmetric quantization
\cite{zhang2023h2o,li2024snapkv,liu2024clusterkv,liu2024kivi}. Their changed resource is an
already-created KV cache. PRA instead chooses provenance-bearing reference and chunk identities
before their payload enters active attention. These techniques are compatible: eviction,
merging, quantization, or future token-level materialization can operate inside PRA's selected
working set. Their errors must then be measured separately from routing errors.

\subsection{Recurrent, Compressive, and Persistent State}

Compressive Transformers, Infini-attention, TransformerFAM, Titans, and selective state-space
models carry forward compressed, recurrent, feedback, learned, or fixed-width state
\cite{rae2020compressive,munkhdalai2024infini,hwang2024fam,behrouz2025titans,gu2024mamba}.
StreamingLLM preserves a chronological attention working set through sinks
\cite{xiao2023streamingllm}. These methods change the state propagated through time and can be
more economical than retaining addressable token detail. PRA preserves separately named source
objects and can revisit selected full-detail K/V out of chronological order. Its implicit prompt
head is the closest overlap, but beyond the native horizon its bounded-block encoding is an
explicit approximation rather than a sufficient recurrent state.

\subsection{Prompt and Context Caching}

PagedAttention manages serving-time KV allocation, while Prompt Cache reuses schema-named prompt
modules and CacheBlend selectively recomputes cached chunks to restore missing cross-chunk
context \cite{kwon2023vllm,gim2023promptcache,yao2024cacheblend}. These systems change where
prompt state resides and how much prefill is repeated. PRA shares their concern with positional
validity, reuse, transfer, and backing storage, but adds semantic routing over addressable
objects and a hard active-K/V admission budget. Conversely, PRA does not yet provide their
serving kernels or throughput evidence; an optimized runtime should build on these systems
rather than treat CPU residency alone as a speed result.

\subsection{Memory-Augmented Networks}

Neural Turing Machines and end-to-end Memory Networks couple a controller to differentiable
external memory and demonstrate content-addressed reads, writes, and multiple hops
\cite{graves2014ntm,sukhbaatar2015memnn}. Hierarchical Attention Networks and adaptive computation
likewise motivate multi-level representation and variable computation
\cite{yang2016han,dehghani2019universal,graves2016adaptive}. PRA inherits the general principle
that access can be learned and iterative. It differs in preserving host-transformer-native K/V,
stable URI identity, cache provenance, and an exact disabled path. Paper 2.5 tests parameter-free
bounded associative discovery, but it is not equivalent to the trained multi-hop controllers in
those systems and does not establish reliable online fault handling.

\subsection{Agentic and Protocol-Level Access}

ReAct and Toolformer coordinate reasoning with external actions
\cite{yao2023react,schick2023toolformer}. They change the action boundary and can search, verify,
or modify the world across model calls. PRA targets a narrower read path for stable or versioned
resources. It does not replace explicit tools, side effects, planning, or verification.

\subsection{MCP and IDE Assistants}

The Model Context Protocol (MCP) defines a client--server interface through which AI applications discover resources, prompts, and tools \cite{mcp2025spec}. IDE assistants similarly expose repository search, symbol navigation, diagnostics, terminals, and version-control state. These systems make external capability discoverable, but the host application still decides how retrieved resource content enters a model context. PRA is complementary: MCP can supply the address space and resolver boundary, while PRA can define how selected resources become internal attention memory.

This combination suggests a layered interface. MCP or an IDE host handles authentication, capability discovery, transport, and side effects. A PRA runtime handles content identity, versioned encoding, cache admission, and model-local use. High-level tool calls should remain explicit and auditable; repeated read-only access to stable resources is the more plausible target for latent memory.

\section{Embodied, Situated, and Referential Memory}

Embodied and enactive approaches argue that cognition is shaped by recurrent interaction among brain, body, and environment rather than by isolated symbol manipulation alone \cite{varela1991embodied}. The extended-mind thesis further asks when reliably available external artifacts participate in a cognitive process rather than merely serving as passive background \cite{clark1998extended}. PRA does not imply that a transformer is embodied or that neural attention reproduces human memory. These traditions instead offer a useful design question: what changes when external structure is not compressed entirely into internal parameters, but remains available through stable, action-conditioned references?

Human activity routinely relies on referential scaffolding. A person remembers that evidence is in a notebook, a clause is in a contract section, a procedure is in a manual, or an explanation belongs to a colleague. The remembered address, cue, and access routine can be more useful than a lossy internal copy. Retrieval is often situated: the object sought depends on the current task, physical or social environment, and sequence of prior actions. Hierarchical cues support progressive refinement from place or document to section and detail.

PRA translates only the computational aspects of this observation. Reference handles are cues; URIs stabilize identity; resolvers implement access routines; routing gists and optional summaries support selection; and layer-specific caches provide a temporary active representation. Recursive anchors make access path-dependent. The analogy predicts that a useful model memory system should preserve provenance and affordances, not only vector similarity. It also predicts failure when the environment is unreliable, addresses become stale, or access policy is ignored.

This perspective broadens evaluation beyond factual recall. A referential memory architecture should be tested on navigation, coordination, revision, and action: whether it can locate the right object, notice when it changed, follow a dependency, respect a permission, and update a plan after new evidence. Those are situated-memory behaviors, not merely next-token improvements.

\section{Enterprise and Professional Applications}

Enterprise information is unusually compatible with context graphs because it already has identifiers, ownership, revisions, links, and permissions. The opportunity is not to pour every enterprise object into a prompt, but to expose a governed address space whose active working set follows the task.

\subsection{Software Engineering}

A software task can begin from repository, branch, commit, package, symbol, test, issue, and build-log handles. GitHub objects and IDE symbol graphs provide stable navigation edges; PRA could keep interfaces and summaries active while materializing implementation bodies or historical diffs only when needed. Required controls include commit-aware cache keys, generated-file labeling, repository permission isolation, and tests that detect stale symbol memory. SWE-bench-style tasks and repository navigation benchmarks can measure whether progressive access reduces loaded tokens without hiding required dependencies.

\subsection{Analytics, BI, and SQL}

Data work spans warehouses, catalogs, SQL schemas, semantic layers, dashboards, lineage graphs, and business glossaries. A Snowflake table, BI metric, or transformation can be a versioned reference with ownership and freshness metadata. The model may first inspect a semantic metric definition, then expand the underlying model, columns, joins, and query history. Evaluation must penalize stale schemas, unauthorized columns, invalid SQL, and semantically wrong but executable queries. Live execution should remain an explicit tool action, while read-only schema memory is a candidate for caching.

\subsection{Organizational Knowledge and Operations}

Confluence pages, Jira issues, runbooks, incidents, and service catalogs form a cross-linked operational memory. Handles can preserve the distinction between approved policy, draft discussion, resolved incident, and current ticket state. Freshness and authority are central: an old runbook should not silently outrank a current service notice. Useful tasks include incident diagnosis, change-impact analysis, status reporting, and tracing a decision from ticket to documentation and code.

\subsection{Scientific Literature}

Scientific assistants need identity at article, version, section, figure, dataset, and claim level. Recursive anchors can move from abstract to method, result, appendix, and cited source. Provenance traces should distinguish quoted evidence from model inference. Benchmarks should test multi-paper synthesis, contradictory findings, retractions, and whether the model can expose the exact evidence path rather than only produce plausible prose.

\subsection{Legal and Medical Assistance}

Legal and medical domains make the risks clearest. Jurisdiction, effective date, patient identity, consent, and source authority are part of meaning, not optional metadata. PRA could help preserve these constraints through versioned, permissioned references and auditable access paths. It must not turn latent memory into an unreviewable decision channel. High-stakes outputs require authoritative-source validation, explicit uncertainty, human review, and strict separation between informational retrieval and actions affecting rights, treatment, or records. Evaluation should emphasize provenance completeness, stale-evidence detection, privacy leakage, and calibrated abstention rather than fluency.

\section{Historical Feasibility Evidence}

This section preserves the experimental path by which the proposal was corrected. The
opening pilot and adaptation study use the optional adapted cross-attention transport,
with a separately normalized memory branch, $W_{O,\mathrm{mem}}$, and a residual scale.
They are labeled historical and must not be read as measurements of canonical native-KV
PRA. Beginning with ``First Native-KV Quality Gate,'' the experiments instead use selected
host-native K/V and progressively repair fragmentation, routing, bounded execution, and
off-device residency. Those studies remain small controlled probes; the companion papers
provide the complete protocols and later pretrained-model evidence.

A standalone PyTorch pilot first provided limited implementation evidence for parts of this position. At 524,288 processed tokens and seeds 1 and 7, mean plain WikiText-2 losses were 4.7691 for SelfAttention, 4.7457 for full PRAttention, and 4.7574 for a two-SelfAttention/two-PRAttention hybrid. More importantly, the old implementation routed one raw summary embedding per reference, collapsed a batch query in an early path, and materialized whole references. We therefore retain all reference-conditioned measurements as engineering history rather than use them for a causal claim about the corrected architecture.

Full and hybrid top-1 are $0.4221\pm0.0156$ and $0.3981\pm0.0397$ against a candidate-count-weighted chance rate of 0.4202. Pretraining improves language competence and final loss, not generalized selection speed. The likely next intervention is a differentiable or explicitly supervised router rather than a larger claim.

A post-refactor smoke rerun now exercises the corrected batched router at fixed total split counts 2 and 5. Twenty tiny CUDA runs share 32 source entries, one BPE tokenizer, context length 128, a fixed data-generation and split seed, and an eight-step budget while pairing model seeds \{1, 7, 21, 42, 87\} across architecture and split count. For full PRA, mean valid-reference loss improves over disabled-reference loss by $0.0189\pm0.0030$ at split 2 and $0.0312\pm0.0048$ at split 5. Every seed has a positive gap, establishing reproducible branch activation. Mean shuffled-reference changes are only $0.0002\pm0.0006$ and $-0.0006\pm0.0009$, however, and split-5 reference top-1 is $0.150\pm0.102$ against a 0.25 uniform-candidate rate. These measurements do not establish the central efficiency thesis. Reference encoding was performed separately for every example on a small GPU, selective triggering was disabled, and cache reuse was not measured. They instead show why the conceptual separation matters: naming and a reference-specific residual can be engineered while selection can still fail independently. The corrected implementation adds the instrumentation and controls needed for a cleaner test, but software completion is not empirical confirmation.

\subsection{First Native-KV Quality Gate}

A subsequent five-seed synthetic experiment isolates native transport from routing and natural-language competence. A two-layer, width-64 SelfAttention model learns to predict a random binary value stored at a fixed historical marker among 63 source units. A disjoint 64-example evaluation set holds the complete source, one-token tail, answer, model weights, and example order fixed while repartitioning source units into 1, 2, 4, 7, 15, 31, or 63 references. Full-context SelfAttention reaches mean loss 0.0105 and 100\% answer-token accuracy; the tail alone reaches loss 1.6999 and 50.6\%, confirming that the target depends on displaced history.

interpretation: it is evidence for separating encoding and routing granularity, not a

\subsection{Sensitivity, Contextual Slicing, and Scale}

A subsequent staged sensitivity study changes the interpretation of the 64-way failure.
Increasing top-$k$ helps the 32-way router but does not repair independently encoded
64-way microchunks, and multi-gist modes do not produce a robust cross-domain winner.
The decisive intervention is to separate encoding context from routing granularity.
Encoding eight consecutive regions together restores five-seed annotated-oracle RCB to
0.996 on HotpotQA-derived text and 0.999 on QASPER-derived text; preserving global

once and slicing its native K/V yields 0.876 and 0.994 at approximately 10\% active K/V.

limit on the number of named regions.

\section{Evaluation Doctrine}

PRA requires counterfactual evaluation because a single task score cannot reveal how memory was used. At minimum, a promising checkpoint should be evaluated with valid references, a disabled reference path, shuffled references, irrelevant references, empty references, oracle references, and all evidence visible in local context. Targets and prompt structure must remain fixed across these conditions. Shuffling must occur across examples while preserving reference count and approximate length, and batched caches must prevent cross-example leakage.

Four families of outcomes should be reported together:

\begin{enumerate}[leftmargin=*]
\item \textbf{Task quality}: loss, perplexity, calibrated accuracy, or task-specific utility.
\item \textbf{Reference and chunk causality}: valid-versus-disabled, valid-versus-shuffled, valid-versus-irrelevant, oracle-chunk, full-reference, and gist-only deltas.
\item \textbf{Preservation}: ordinary language and non-reference task quality before and after adaptation.
\item \textbf{Resource use}: processed tokens, available versus selected memory tokens, synchronized cache/routing/attention latency, bucket padding ratio, throughput, peak memory, cache bytes, and reuse rate.
\end{enumerate}

Evidence of genuine reference use requires more than a disabled-path gap. A branch can act as a generic domain adapter regardless of supplied content. Valid references should outperform shuffled and irrelevant content, ideally by larger margins on examples proven to be locally insufficient. Reference routing and chunk routing should separately rank known relevant objects and evidence spans above controls. Claims should be repeated across seeds and reported with matched token, parameter, and compute budgets.

\section{Research Agenda}

The original agenda proceeded through controlled standalone models, positional validation,
and pretrained integration. Those stages now have dedicated companion papers. The remaining
agenda begins at the measured one-shot boundary rather than repeating completed integration
work.

\paragraph{Standalone controlled models.}
Continue to use small decoder-only transformers for mechanism isolation. The corrected studies
now cover paired counterfactuals, native-KV transport, contextual slicing, fixed-$k$ and
fixed-fraction scaling, learned routing geometry, and model-bounded prompts. Their role is to
falsify mechanisms cheaply, not to stand in for pretrained task evaluation.

\paragraph{Pretrained-model integration.}
Paper 2 wraps pretrained Hugging Face families while preserving rotary conventions,
grouped-query layout, cache formats, and exact disabled behavior. The released SDK makes
one-shot PRA usable for research and sparse direct-memory workloads. The next integration
question is not whether wrapping is possible, but how routing and conditional memory use
generalize across domains, depths, model scales, and realistic retrieval errors.

\paragraph{Runtime and serving integration.}
Study how reference memories are resolved, encoded, cached, paged, shared, and evicted. Add
asynchronous host-to-device transfer, fused route-and-attend kernels, batching, approximate
indexes, and matched dense/RAG baselines. The central metric is no longer only accuracy, but
quality per materialized token, millisecond, transferred byte, and resident byte. The current
SDK is usable, and Papers 3 and 3.5 add controlled interval materialization, adaptive-effort,
index, gather, paging, and batching prototypes.  These are mechanism and prototype measurements;
a generally compelling production architecture and its serving economics are not yet established.

\paragraph{Scaling and theory.}
Run the decisive 32K--8M+ logical-memory protocol defined above on task families where relevant
context occupies a controllable fraction of the available corpus.  Separate active GPU native-K/V
from CPU/reference storage and search/index cost. PRA should be evaluated against full-context,
sparse-attention, RAG, summary-first RAG, and agentic-search baselines.

\paragraph{Selection and gating.}
Compare projected content gists, explicit reference-token attention, optional summaries,
learned routers, uncertainty triggers, and hybrid policies while holding selected native-KV
transport fixed. Paper 1.5 shows that reproducing native Q/K geometry does not guarantee a
useful semantic index, and Paper 2 shows domain-dependent learned routing. Reference and chunk
selection should be evaluated through recall--sparsity curves, MRR, NDCG, span IoU,
counterfactual task loss, and learning speed, not only whether an expected URI entered a cache.

\paragraph{Hierarchical expansion.}
Paper 2.5 implements bounded associative discovery for tasks in which the initial query identifies
an intermediate relation but not the final evidence.  It establishes synthetic mechanism
controls and natural native-edge topology, while also exposing weak executable entry routing,
granularity-dependent missing edges, and broad activation.  The next step is not another
uncontrolled depth sweep.  It is calibrated online entry/search control coupled to the
evidence-centered disclosure policies tested in Paper 3, with retry and stopping evaluated as one
causal loop.  Measure expansion depth, branching factor, missed-evidence rate, repeated-route cost,
and quality per resolved and materialized token.  Flat single-hop tasks cannot test the progressive
part of PRA.

\paragraph{Training and preservation.}
Compare isolated reference-path adaptation, joint fine-tuning, adapters, low-rank updates, and curriculum mixtures. Report both reference improvement and local-task retention. Determine whether zero-initialized memory residuals remain stable at larger scale and whether learned gates avoid permanent saturation.

\paragraph{Safety, provenance, and access control.}
Treat reference resolution as a privileged operation. Study signed or versioned URIs, tenant isolation, policy-aware cache keys, provenance traces, revocation, poisoning detection, and whether the model can infer protected content through shared memory representations.

\subsection{Falsification Criteria}

The research program should be abandoned or substantially revised if repeated, well-controlled studies show any of the following:

\begin{itemize}[leftmargin=*]
\item valid references do not outperform shuffled or irrelevant references once formatting and capacity are controlled;
\item equivalent prompt concatenation or RAG matches quality at lower end-to-end cost;
\item reference encoding and cache management erase any savings from shorter local context, even with reuse;
\item learned expansion policies fail to outperform simple oracle-budgeted retrieval or cannot maintain recall;
\item local language ability degrades unacceptably under the adaptation needed to use memory;
\item URI and cache isolation cannot be enforced under realistic batching and multi-tenant serving.
\end{itemize}

These criteria make PRA a testable systems-and-model hypothesis rather than a label that can absorb any retrieval mechanism after the fact.

\section{Risks and Limitations}

PRA introduces several risks. First, reference selection can fail silently: if the system does not select the right chunk, the model may answer from incomplete context. Second, URI-addressed memory creates provenance and security questions. A reference table is a powerful interface; poisoning or misaddressing entries can mislead the model. Third, cache construction may move cost rather than eliminate it. Encoding references separately is only beneficial when cache reuse, selective transfer, or reduced prompt length outweighs encoding overhead. Fourth, pretrained integration is family-specific because external K/V must respect layer semantics, position encodings, attention variants, and batching constraints. Paper 2 demonstrates exact adapters for multiple tested families, but not universal compatibility.

Fifth, content-independent branch effects can be mistaken for retrieval. A memory residual may improve a domain simply because it contributes additional activations, even when references are shuffled. Sixth, batching can violate semantic isolation: a physically shared cache must not expose one sequence's references to another, and empty rows must not inherit projection bias. Seventh, preservation claims can be artifacts of freezing rather than architecture. Eighth, hierarchical expansion can amplify latency variance and create denial-of-service surfaces when references recursively fan out. Ninth, raw summaries can introduce a representation mismatch when compared with projected layer queries; optional summary evidence must inhabit the same contextual layer space. Tenth, implicit prompt heads move historical encoding into a separate cold pass; bounded blocks approximate full historical context, and streaming currently rebuilds the complete head after rollover rather than appending K/V incrementally. Eleventh, CPU residency reduces measured GPU capacity but the current per-chunk offload makes cold construction slower. Finally, stale cache entries create a consistency problem: URI, content version, model/tokenizer/routing fingerprints, and encoded layer memory must remain aligned.

These limitations motivate careful experimental design. PRA should not be judged by a single accuracy number. It should be evaluated through controlled ablations that measure answer accuracy, reference and chunk ranking, expansion depth and budget exhaustion, logical, requested, and materialized fractions, timing decomposition, padding allocation, cache hit ratio, content-specific counterfactual deltas, ordinary-path retention, and cache isolation. The series now addresses tiny-scale capacity, positional continuity, learned semantic routing, exact pretrained retrofit, long-prompt displacement, selective transfer, measured GPU residency, bounded associative discovery, controlled evidence-centered materialization, and prototype adaptive effort. Sparse end-to-end iterative benefit, disclosure generalization, batched asynchronous offload, multi-million-token scaling, and efficiency against strong production baselines remain open.

\section{Conclusion}

Progressive Retrieval Attention proposes a shift in how foundation models interact with memory. Rather than treating context as a flat token budget to be filled eagerly, PRA treats references as first-class computational objects that can be named, selected, materialized, attended to, expanded, reused, revoked, and audited. The model's logical context may then be much larger than its active working set, just as a program's address space can exceed resident memory. Unlike conventional paging, however, neural materialization is approximate and learned; success must be demonstrated, not presumed.

The program's long-term hypothesis is deliberately stronger than its present evidence: a scalable
neural memory architecture may separate local computation from sparse, externally backed,
content-addressed memory; progressively disclose only the native state required by the current
computation; adapt retrieval effort to uncertainty; and learn representations that remain useful
under this sparse memory interface.  No current paper demonstrates that complete architecture.

The long-term vision is a foundation-model memory stack with explicit boundaries among parametric knowledge, working context, episodic history, semantic resources, procedures and tools, and changing world state. URI identity, provenance, freshness, hierarchy, permissions, and cache lifetime become architectural concerns rather than application-side annotations. Protocols such as MCP can expose resources and actions, agents can manage high-level plans, and PRA-like runtimes can test whether repeated read-oriented access can move closer to attention without losing governance.

The historical cross-attention follow-up supports preservation controls but fails its
content-causality gate. Native-KV experiments provide stronger mechanism evidence: contextual
slicing preserves transport through 256 addressable units, fixed-$k$ active fraction falls to
roughly 5\%, and model-bounded encoding demonstrates a logical head 5.75 times the native limit.
Paper 1.5 adds positional continuity and separates semantic search from native attention geometry.
Paper 2 then establishes exact disabled pretrained paths, cross-family adapters, and a useful
one-shot QASPER regime while identifying HotpotQA as the multi-hop boundary. Paper 2.5
demonstrates bounded associative discovery and native graph structure, while showing that entry
competition, granularity, broad activation, and memory-use interference still limit sparse
end-to-end gains.  Paper 3 adds controlled evidence-centered disclosure and corrected Qwen
consumer-placement evidence; Paper 4.5 turns the four layer roles into versioned, cross-model
runtime profiles.  Those results support coherent late bands for the tested MuSiQue/2Wiki replay
but broader parity profiles for the tested Qwen, Llama, and Gemma topologies, not a universal depth
rule.  Paper 3.5 adds observable-only effort control and runtime prototypes; none establishes
production speed.  Together these results make PRA a usable research SDK and
support the narrow claim that named logical context can grow faster than the K/V materialized in
one operation. They do not yet show that PRA is generally better than optimized long context or RAG
in production. The decisive next tests are learned sparse-memory assimilation, the matched
32K--8M+ scaling experiment, and production serving under realistic batching and cache pressure;
failure there should narrow or reject the broader virtual-context thesis.
