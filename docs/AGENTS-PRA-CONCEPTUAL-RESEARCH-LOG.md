## 1. Logical memory can exceed native operation size

PRA separates several quantities that ordinary dense transformers often collapse into a single notion of **context length**:


- **`L_logical` — logical/addressable context length.**
  The total amount of information that the current computation can potentially access through the direct prompt, `#__head`, explicit URI references, and other PRA-addressable memory. For example, a request may expose 128K tokens of logical memory even though only a small fraction is active in any individual attention operation. `L_logical` can therefore grow through external references, streaming history, and off-device memory without requiring all those tokens to coexist in one native attention tensor.

- **`L_model_op` — maximum native model-operation length.**
  The maximum number of token positions permitted in any individual operation performed by the underlying transformer. This constrains bounded reference encoding, `#__head` encoding, direct prompt processing, and the final combination of direct and materialized memory used by attention. PRA enforces a constraint of the general form:

  \[
  L_{\text{direct}}
  +
  L_{\text{materialized}}
  +
  L_{\text{reserve}}
  \le
  L_{\text{model-op}}.
  \]

  A model can therefore have access to 128K tokens of logical memory while never performing a native attention operation over more than, for example, 4K tokens.

- **`L_position` — positional-coordinate capacity or usable positional range.**
  The range of logical positions that the model's positional mechanism can represent or meaningfully use. This is distinct from how many tokens are processed simultaneously. For learned absolute embeddings, `L_position` may be bounded by the learned position table. For sinusoidal or RoPE mechanisms, positions can be generated mathematically beyond a finite lookup table, although useful extrapolation beyond the model's training distribution remains an empirical question. A 4K native operation can therefore, in principle, contain selected tokens whose logical source positions lie much farther apart.

- **`L_train` — positional/context range represented during training.**
  The range and distribution of sequence lengths and relative token distances under which the model actually learned its attention behavior. This is conceptually different from `L_position`: a positional mechanism may be mathematically capable of representing position 100K while the model has little or no training experience using dependencies at that distance. This distinction is particularly important for RoPE, where a relative rotation can be mathematically well defined without implying that the learned Q/K representations behave usefully at that relative distance.

The important PRA distinction is therefore:

\[
L_{\text{logical}}
\neq
L_{\text{model-op}}
\neq
L_{\text{position}}
\neq
L_{\text{train}}
\]

in general.

For example:

```text
L_logical   = 128K   total addressable prompt + memory
L_model_op  =   4K   maximum tokens in any native operation
L_position  = 128K+  positional coordinates mechanically supported
L_train     =  32K   illustrative range/distribution seen during training


Paper 1 controlled experiments and Paper 2 Qwen `#__head`/CPU-resident memory show that logical memory can exceed any one native operation while every actual operation remains bounded.

**Status:** strongly supported engineering mechanism. It does not prove retrieval quality at arbitrary scale.

## 2. Sparse working set is distinct from total memory
Fixed sparse materialization can keep active attention K/V bounded as addressable memory grows. Actual GPU-capacity savings require CPU/off-device residency, paging, eviction, or tiered storage.

**Status:** strongly supported.

## 3. Routing-quality scalability is a separate gate
Paper 1 showed routing breadth becomes increasingly important as candidate count grows, especially on QASPER. Paper 2 showed HF engineering scalability can work while semantic routing fails.

> **Sparse memory scaling and routing-quality scaling are separate problems.**

**Status:** strongly supported.


## 4. Routing representation is not attention representation
Canonical memory abstraction:

`M_c = (R_c, K_c, V_c)`

where `R_c` is the routing/index representation and `K_c,V_c` are native attention payload.

Qwen zero-shot routing produced the qualitative ordering:

```text
attention-input hidden state
>
pre-RoPE K
>
post-RoPE K
```

Post-RoPE routing showed strong source-position bias. Hidden-state routing was best among tested zero-parameter sparse routers, although still below the promotion gate.

Interpretation:

```text
h_in
→ broad contextual state

W_K(h_in)
→ attention-address representation

RoPE(W_K(h_in))
→ position-conditioned attention-address representation
```

Canonical principle:

> **Route with semantic state; attend with native positional state.**

**Status:** strongly supported for current Qwen; cross-family generality remains open.

## 5. Why post-RoPE K is a poor naive semantic index
`K_post(p)=R(p)K_pre`.

A post-RoPE mean gist averages differently rotated vectors:

`mean_j[R(p_j)K_pre,j]`.

Native QK attention respects the RoPE relative-rotation algebra; ordinary semantic averaging, cosine retrieval, clustering, and approximate-position matching do not automatically do so.

Preferred wording:

> **RoPE positionally multiplexes attention-address features. Post-RoPE K is correct for native attention but can be a poor conventional semantic indexing space.**

Do not say RoPE destroys semantics.

**Status:** mathematically motivated and experimentally supported in Qwen.

## 6. Positional vs contextualization fragmentation
Chunking creates distinct errors.

**Positional fragmentation:** source chunk is reset to local position zero instead of `p_j=s+j`.

**Contextualization fragmentation:** independently encoded chunks do not see the same preceding context as dense encoding.

Paper 1.5 logical offsets eliminated layer-0 reset error across learned-absolute, sinusoidal, and RoPE models and improved deeper K fidelity. Residual deeper error remained. Overlap/history/larger encoding context improved representation fidelity.

> **Logical offsets repair positional fragmentation; contextual encoding repairs contextualization fragmentation.**

**Status:** strongly supported.

## 7. Exact RoPE offsets recover relative position exactly
Dense RoPE uses `R(i)Q_i` and `R(j)K_j`, so matching depends on `R(j-i)`.

If chunk start `s` and local index `r` recover `j=s+r`, PRA reconstructs the exact original RoPE relative position.

Therefore:

> **If underlying pre-RoPE Q/K are unchanged, exact logical offsets introduce no RoPE positional error.**

Because rotation is orthogonal:

`||R(p)K_a-R(p)K_b|| = ||K_a-K_b||`.

Remaining differences must come from contextual representation, selection, composition, sparse topology, or another implementation condition.

**Status:** mathematically established; layer-0 experiments support it.


## 8. Representation fidelity does not imply task utility
Paper 1.5 found robust representation improvements from logical offsets while WikiText and QA task improvements were mixed; RoPE task means could worsen despite better positional fidelity.

> **Representation correctness and functional usefulness are different outcomes.**

> **Correct coordinates recover positional identity but do not reconstruct missing causal/contextual information.**

**Status:** strongly supported.

## 9. Geometric correctness vs functional positional policy
For continuous memory, exact logical offsets are the geometrically faithful reconstruction.

Changing effective query-memory distance `D` is therefore not a RoPE correction. It is an intentional alternative memory-integration policy.

Planned experiment preserves local geometry while changing global distance:

`p'_j = q-D+j`.

Question:

> Once retrieval changes available-memory topology, should original serialization distance remain the best functional geometry?

**Status:** open / planned Paper 1.5 experiment.

## 10. Serialization geometry vs functional dependency
Semantic dependencies need not follow raw token distance. For unrelated URI documents there is no naturally correct global token distance to the query.

Retrieval exposes relevance relations that can differ from serialization geometry.

Adaptive `D`, semantic-distance `D`, graph/MST geometry, and learned positional routing are later work.

**Status:** conceptually motivated, experimentally open.

## 11. Selection vs composition
Paper 1.5 evidence-only oracle conditions were not universally best.

Distinguish:

```text
selection:
which chunks are chosen?

composition:
which combination of chunks actually helps prediction?
```

Potential causes include supporting context, distractors, redundancy, and interactions.

> **Evidence identification and useful memory composition are distinct problems.**

**Status:** suggested/partially supported.

## 12. Multi-gist multiplicity alone is insufficient
`segment_mean` divided a 32-token hidden-state routing chunk into contiguous submeans.

Reported Paper 2 confirmation approximately:

```text
G=1 Recall@3 .391
G=2          .313
G=4          .266
G=8          .281
```

MRR also worsened. G=8 helped broad Recall@16 but increased routing-index overhead.

> **Simply increasing the number of query-independent contiguous means does not solve sparse semantic ranking.**

This weakens the hypothesis that the primary problem is merely evidence dilution inside one arithmetic mean.

**Status:** strong negative result for this strategy.


## 13. Segment-mean failure points toward alignment
The current bottleneck may be query-memory alignment rather than only routing-vector resolution.

No objective trained cosine similarity between query hidden state and chunk-mean hidden state to mean “contains evidence required by this query.”

Measured discriminating diagnostic:

`score(c)=max_t sim(h_query,h_t)`.

On the matched 16-example subset, token-level hidden-state maximum routing changed Recall@3
from `.438` to `.375`. HotpotQA MRR improved, but QASPER MRR and Recall@3 worsened, while the
routing index grew from about `1.57%` to `50%` of detail-K/V bytes.

Interpretation:

```text
token-level strong, mean weak
→ pooling remains important

token-level weak
→ learned query/evidence alignment likely required
```

The result favors the second explanation: finer resolution alone is insufficient, especially
on QASPER. Next intervention: freeze Qwen and train a tiny routing projection, beginning linear.

**Status:** alignment hypothesis strengthened.

## 14. Native attention compatibility is not semantic evidence relevance

Centered-RoPE routing tested a final zero-parameter K-space hypothesis:

`g_center = R(p_center) mean(K_pre)`

This avoids averaging keys from incompatible positional frames while assigning one exact known
representative position. On 16 matched HotpotQA/QASPER examples:

```text
router                    Recall@3   MRR    position r
post-RoPE mean              .125     .131      .651
centered-RoPE mean          .188     .168      .567
pre-RoPE mean               .313     .301      .008
hidden-state mean           .438     .275     -.021
```

Centered segment gists increasingly reproduced native token-QK maximum ordering as `G` grew:

```text
G                         1      2      4      8
native-max rank corr.   .521   .602   .710   .874
Recall@3                .188   .125   .250   .250
```

Thus the mechanism works as an approximation to native attention geometry, but semantic
evidence recall does not improve in proportion. Exact fractional, floor, and ceil centers had
the same Recall@3 on the matched fractional control, so half-position support is not the
explanation for weak routing.

> **A routing representation can become substantially more faithful to native token-attention
> ordering without becoming a better semantic evidence index.**

This strengthens the independent memory abstraction `M_c=(R_c,K_c,V_c)`: optimize `R_c` for
selection, while retaining exact native post-RoPE `K_c,V_c` for attention after selection.

**Status:** strongly supported on the current Qwen subset. Freeze further zero-parameter
transform invention unless a new discriminating hypothesis appears; proceed to a tiny learned
hidden-state alignment router.

## 14a. The final hidden state remains the best hand-designed information-need query

The query study held memory fixed at one attention-input hidden-state mean per 32-token chunk.
On 32 identity-disjoint confirmation examples:

```text
query                         Recall@3   Recall@8   MRR
last state                       .469       .719    .413
question decay, half-life 2      .250       .688    .279
uniform recent 32                .313       .469    .348
```

The aggregates genuinely changed geometry (cosine to last `.459` and `.576`) but did not improve
relevance. Long-window averaging appeared less harmful for the small long-question subgroup,
but the split confounds dataset and length and is not sufficient for a conditional policy.

**Interpretation:** a causal final state already contains a more useful complete information need
than means of earlier, partially formed states. Query aggregation is not the dominant zero-shot
bottleneck. Keep `last` as the canonical query.

## 14b. Learned relevance geometry helps, but current evidence is objective- and dataset-specific

A frozen-Qwen adapter study used 48 train, 16 validation, and 32 held-out test examples with no
identity leakage. The first contrastive stage selected an asymmetric 1024-to-128 query/memory
projection. Across five seeds its held-out result was:

```text
metric                         Recall@3   Recall@8   MRR   Hotpot R@3   QASPER R@3
cosine last                       .469       .719    .413      .813         .125
asymmetric-128 selected           .563       .806    .516      .400         .725
```

The adapter has 262,144 parameters (`.044%` of Qwen). It greatly improves QASPER but gives away
much of HotpotQA and misses the predeclared `.70` combined gate. A shared 64-dimensional adapter
reaches `.650` test Recall@3, but that is post-hoc test-best evidence, not the validation-selected
confirmatory model. Shuffled-label Recall@3 is `.231`. Hotpot-to-QASPER transfer is `.150`, and
QASPER-to-Hotpot transfer is `.225`.

The adapter therefore demonstrates that learned alignment can matter more than representation
resolution, but not yet that it learns a reusable relevance geometry. In the real PRA generation
path, the selected adapter recalled evidence on 4/8 probes while answer F1 remained exactly
`.090` with and without PRA.

> **Routing alignment and causal memory use are distinct trainable interfaces. Better evidence
> selection does not imply that a frozen decoder will use selected native K/V to answer.**

An extension then tested the missing 256-dimensional capacity rung, a pairwise margin objective,
mixed lexical/position/current-router negatives, and one learned-hard-negative refresh. Selection
remained validation-only. The margin objective, not width or mining, revised the canonical result:

```text
condition                         R@3    R@8    MRR    Hotpot R@3   QASPER R@3
zero-shot cosine                 .469   .719   .413       .813          .125
contrastive asymmetric-128       .563   .806   .516       .400          .725
margin asymmetric-128            .631   .806   .498       .588          .675
contrastive shared-256           .631   .819   .558       .500          .763
mixed negatives                  .538   .819   .494       .313          .763
mined round 1                    .506   .825   .479       .288          .725
```

The margin router improves paired Recall@3 by `.163 +/- .069` (95% half-width across five seeds),
reduces score-position correlation to `-.026`, and uses a 128-dimensional index equal to `.392%`
of native detail-K/V bytes. It passes the per-dataset, Recall@8, position, and width gates, but
still misses combined Recall@3 `.70`. Shuffled-label Recall@3 falls to `.125`, while both
cross-domain directions reach only `.213`. One hard-negative refresh worsens sparse recall,
which argues against insufficient false-positive mining as the current explanation.

The selected seed recalls evidence on `5/8` end-to-end probes, but answer F1 remains exactly
`.090` with and without PRA. This strengthens rather than weakens the separation between
selection and use.

> **For this frozen Qwen study, learning the ranking objective matters more than increasing
> routing resolution or adapter width. The remaining failures are transfer and causal use, not
> an obvious shortage of router parameters.**

**Status (revised):** learned-alignment hypothesis supported more strongly; domain-general
routing and causal-use claims remain unsupported. Do not promote to Llama. Increase routing-data
diversity before capacity, then study memory-use alignment only after retrieval generalizes.

## 14c. Fixed-k stress tests can conceal a useful fractional operating range

Observation:
- The validation-selected learned router fails the predeclared combined Recall@3 gate at 0.631.
- Recomputing selection per example as `ceil(f * candidate_chunks)` gives any-evidence recall
  0.831 at 10% and 0.956 at 20%, with realized `f80=0.105`, `f90=0.158`, and normalized
  `AUC0-30=0.835`.
- The parameter-free last-state query reaches 0.719 and 0.875 at the same fractions.
- On artifacts with exact parent lengths, realized K/V fraction differs from realized chunk
  fraction by less than 0.2 percentage points because almost all parents contain 32 tokens.

Original hypothesis:
- Failure at very small fixed `k` implied that no useful sparse routing regime had emerged.

Experiment:
- Historical rankings were reevaluated at 1, 2, 5, 10, 15, 20, 25, 30, 50, and 100 percent,
  using a per-example ceiling and first-measured inverse thresholds.
- Complete frozen-feature rankings additionally measured all-evidence coverage against physical
  native-K/V token fraction.

Result:
- Negative for the original broad interpretation of the Recall@3 failure.
- Positive for a practical 10--20% candidate-selection regime.
- Still negative for cross-domain transfer and causal answer improvement.

Interpretation:
- Fixed `k` and fixed fraction answer different scaling questions. PRA evaluations should report
  both, with materialized K/V fraction preferred when physical lengths are available.
- Any-evidence recall and all-evidence coverage are not interchangeable, especially for HotpotQA.

Alternative explanations:
- Several zero-parameter mechanisms use an older 16-example cohort, so their curves are
  descriptive rather than paired with the 32-example, five-seed learned-router study.
- Annotated evidence may not equal the functionally optimal memory composition.

Claim status:
- Strong for metric design and the selected adapter's measured operating curve.
- Preliminary for broad benchmark or model-family generalization.

Next discriminating experiment:
- Preserve complete rankings and physical parent lengths automatically in future runs, then
  repeat fraction curves on larger identity-disjoint cohorts and test whether the 10--20%
  retrieval gain changes answer quality.

Affected papers:
- Paper 2 immediately; Papers 1 and 1.5 receive mechanism-appropriate retrospectives.

## 14d. Correct evidence can be attended without being used productively

Observation:
- Learned-router evidence recall and answer quality can diverge because selection and
  consumption are separate causal gates.
- On four HotpotQA examples, forcing every evidence-parent chunk at the last four layers raises
  paired mean gold-token log-probability by 1.004 nats/token; direct evidence text raises it by
  4.635. One and two upper layers give only +0.071 and +0.233.
- On four QASPER examples, last-four oracle memory changes the score by -0.161 while direct text
  changes it by -1.791. Oracle memory nevertheless receives 0.615--0.645 attention mass.
- The follow-up depth sweep revises the narrow last-four diagnosis. HotpotQA oracle memory gives
  +2.311 at the last eight layers and +3.641 at the last half, compared with +4.635 for direct
  text. All 28 layers give -0.766. QASPER is +0.347 at last eight but its direct-text control
  remains negative.
- Equal-count placement is decisive: early four, evenly spaced four, and every fourth layer give
  combined changes of -10.573, -10.398, and -6.090, while contiguous late four and late seven
  give +0.421 and +1.128.
- Route-once learned retrieval through the last eight layers gives +0.227 combined while
  preserving F1; the bounded `#__head` rank-1 fact gives +5.469 but remains absent from greedy
  output.

Original hypothesis:
- If exact evidence identities are supplied through faithful native K/V, a frozen decoder should
  improve answer likelihood; otherwise the dominant defect is memory-use alignment.

Experiment:
- Compare no memory, evidence-oracle PRA at last-one/two/four/eight, last-quarter, last-half, and
  all layers; follow with matched-count early, middle, late, even, and every-fourth placement.
- Route once at layer 27 with the selected learned router or raw hidden-state cosine, reuse only
  parent IDs, and resolve each consuming layer's own native K/V.
- Force identities only at `prepare_selected_memory`, preserving the ordinary budget,
  post-RoPE K/V, source positions, GQA, transfer, mask, and Qwen eager-attention path.
- Record teacher-forced answer likelihood and first-token rank before generated EM/F1, together
  with attention mass, hidden-state deltas, active K/V, timing, and per-example traces.

Result:
- Positive for causal native-memory use on HotpotQA through a contiguous late band and for the
  bounded implicit head's teacher-forced answer likelihood.
- Positive but smaller for route-once learned retrieval at the last-eight operating point.
- Negative for generated-quality improvement.
- Inconclusive for PRA memory use on QASPER because the direct-text upper control also fails.

Interpretation:
- PRA consumption is layer-depth dependent; evidence in one upper layer is not equivalent to
  evidence available across several late transformations.
- Layer placement is not interchangeable. Earlier exposure and sparse depth do not compensate
  by leaving more downstream layers; they can be catastrophically incompatible with the local
  residual stream. All-layer replay is also harmful, so the mechanism is a late band rather
  than maximal depth.
- Chunk identity can be routed once while payload remains layer-native. Routing depth and
  consumption depth are now experimentally separate controls.
- High attention mass and large hidden-state perturbation do not establish useful consumption.
- A direct-text evidence control is mandatory before assigning a negative oracle-PRA result to
  transport or alignment.

Alternative explanations:
- Each dataset has only four deterministic examples, Qwen3-0.6B is weak at generated QA, and
  condition order is fixed.
- Annotated evidence parents include surrounding tokens and may not be the optimal composition.
- Teacher-forced likelihood can reveal movement that greedy generation does not cross.

Claim status:
- Preliminary but causal for the paired HotpotQA likelihood intervention.
- Unsupported for end-task accuracy, QASPER, larger checkpoints, and other model families.

Next discriminating experiment:
- Replicate the HotpotQA late-eight/late-half frontier on a larger identity-disjoint sample with
  randomized condition order and a checkpoint-solvable generation protocol. Do not add a
  learned memory-use gate yet: frozen Qwen already demonstrates causal use.

Affected papers:
- Paper 2 main results and implementation appendix; Paper 0 only after larger replication.

## 14. Multi-layer routing
Hypothesis: best semantic routing depth may differ from later PRA consumption depth:

`l_route != l_PRA`.

Potential architecture:

```text
middle h_in
→ route once
→ selected chunk IDs

later PRA layer 20 → K20/V20 for IDs
later PRA layer 21 → K21/V21 for IDs
```

Potential benefits: better semantics and fewer repeated routing calls while preserving layer-native K/V.

**Status:** route-once at layer 27 with last-eight/last-half consumption is complete in Paper 2.
Semantic routing-depth optimization remains a Paper 3 question.

## 15. Multi-gist and multi-layer are orthogonal
Represent routing state as `G_c^(l,i)`:

```text
l = routing layer
i = gist/prototype within layer
```

Questions:
1. At what depth should routing happen?
2. How many representatives should summarize the chunk at that depth?

Do not run the full Cartesian product initially.

## 16. Route once vs route every PRA layer
Compare independent per-layer routing with route-once chunk-ID reuse. Later layers still consume their own K/V; never reuse one layer's K/V at another layer.

Route-once evidence now includes task likelihood, generated F1, full ranking curves, query and
routing latency, and aggregate per-layer materialization. Independent per-layer routing remains
an open Paper 3 comparison because it changes selection and consumption simultaneously.

## 17. Positive and negative results both shape architecture
Important negative results include:

```text
positional fidelity improved
→ task quality did not reliably improve

post-RoPE routing
→ position biased

pre-RoPE routing
→ better but not best

attention-input hidden mean
→ best zero-shot but still insufficient

segment_mean

```

These eliminate simplistic explanations and justify smaller, more discriminating next experiments.

## 18. Current canonical PRA decomposition

```text
1. REPRESENT
   build compact semantic routing state R

2. SELECT
   choose memory identities / chunk IDs

3. POSITION + CONTEXTUALIZE
   preserve or deliberately assign positional semantics;
   encode detail memory with adequate context

4. CONSUME
   materialize layer-native K/V and perform native attention
```

This is more general than “query K against a K-derived gist.”


## 19. Connection to computational/cognitive theory
PRA is an experimental probe, not itself a cognitive theory.

Potential general distinctions exposed:

```text
relevance vs metric proximity
stable semantic identity vs context-dependent addressing
selection vs integration
local relational precision vs remote dependency
representation fidelity vs behavioral utility
```

These can be compared with a broader local-rule/stability-hierarchy theory in which cognition must maintain stable representations, detect relevant perturbations, propagate dependencies, stabilize invariants, form abstractions, select stored structure, integrate it into current dynamics, and adapt continually.

Transformer analysis, local-rule/biological models, and computational theory should cross-inform one another rather than be forced into one narrative.

## 24. Current high-level thesis
Do not treat this as established; keep revising it.

> **Long-context transformer memory is not one problem. It requires distinct mechanisms for representing relevance, selecting memory identity, preserving contextual and positional structure, composing selected memories, and consuming them through layer-native computation. Several failures arise when one representation or geometry is forced to serve all of these roles.**

This is the current unifying interpretation of the PRA experimental program.
